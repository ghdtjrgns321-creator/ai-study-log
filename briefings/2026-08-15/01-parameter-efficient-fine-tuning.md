# 오늘의 AI 개념: 파라미터 효율적 미세조정(Parameter-Efficient Fine-Tuning, PEFT) — LoRA·QLoRA

> 작성일: 2026-08-15 · 분류: ai-concept

## 한 줄 정의

거대한 AI 모델 전체를 다시 학습시키지 않고, 그 옆에 붙인 작은 부품만 학습시켜 특정 업무에 맞게 바꾸는 기법이다.

## 쉬운 설명

일반적인 파인튜닝은 사전학습된 대형 언어모델(LLM, 거대언어모델)의 가중치 전체를 다시 조정한다. 모델이 클수록 GPU 메모리와 시간이 기하급수적으로 늘어나, 700억 개 파라미터급 모델을 통째로 재학습하려면 고가의 GPU 여러 대가 며칠씩 필요하다.

LoRA(Low-Rank Adaptation, 저순위 적응)는 원본 모델의 가중치는 그대로 얼려 두고, 층마다 작은 행렬 두 개로 이루어진 "어댑터"만 새로 붙여 그 어댑터만 학습시킨다. 학습 대상 파라미터 수가 원본의 0.1% 미만으로 줄어, 결과물도 원본 모델 전체가 아니라 수십~수백 메가바이트짜리 어댑터 파일 하나로 남는다.

QLoRA(Quantized LoRA, 양자화 LoRA)는 여기에 한 단계를 더한다. 원본 모델 가중치를 4비트로 압축(양자화)해 GPU 메모리에 올려 두고, 그 위에 LoRA 어댑터만 학습시킨다. 이 덕분에 700억 개 파라미터급 모델도 소비자용 GPU 한 장으로 미세조정할 수 있게 됐다.

비유하자면 원본 모델을 다시 만드는 완전 파인튜닝은 사람을 처음부터 다시 교육하는 것이고, LoRA·QLoRA는 이미 정규교육을 마친 사람에게 회사 업무에 필요한 부분만 짧게 입사교육을 시키는 것과 같다. 기반 지식은 그대로 두고, 업무에 필요한 판단 습관만 얇게 덧입히는 방식이다.

## 동작 원리

1. 사전학습된 모델의 가중치 행렬 W는 학습 중 값이 바뀌지 않도록 고정(freeze)한다.
2. 그 옆에 두 개의 작은 행렬 A, B로 이루어진 저순위(rank) 어댑터를 추가한다. 순위 r(보통 4~64)이 작을수록 학습 파라미터가 적어진다.
3. 추론 시 실제로 쓰이는 가중치는 W + A×B(스케일 계수 alpha 적용)이며, 학습 과정에서는 A와 B만 역전파로 갱신한다.
4. QLoRA는 1단계 전에 W를 4비트 NormalFloat(NF4) 형식으로 양자화하고, 양자화 상수 자체도 다시 양자화(이중 양자화)해 메모리를 더 줄인다. 학습 중 메모리 급증을 막기 위해 페이지 단위 옵티마이저도 함께 쓴다.
5. 학습이 끝나면 어댑터(A, B)만 저장한다. 배포할 때는 기존 원본 모델에 어댑터를 얹기만 하면 되므로, 하나의 기반 모델에 업무별 어댑터를 갈아 끼우며 운용할 수 있다.

## 구체 예시·사례

700억 개 파라미터 모델을 완전 파인튜닝하려면 옵티마이저 상태까지 포함해 GPU 메모리가 수백 기가바이트 필요해 고가 GPU 여러 대를 묶어야 한다. 같은 모델을 QLoRA로 미세조정하면 필요한 메모리가 수십 기가바이트 수준으로 줄어, 소비자용 GPU 한 장으로도 가능해진다.

기업 현장에서는 하나의 기반 모델에 "회계 계정과목 분류용 어댑터", "계약서 리스크 조항 추출용 어댑터"처럼 업무별로 서로 다른 LoRA 어댑터를 만들어 두고, 요청 종류에 따라 필요한 어댑터만 바꿔 끼워 서비스하는 방식이 실무에서 쓰인다. 어댑터 하나의 용량이 작아 여러 개를 동시에 GPU에 올려두고 전환하는 것도 부담이 적다.

## 비슷한 것과 비교

| 방식 | 학습 대상 | 필요 자원 | 장점 | 한계 |
|------|-----------|-----------|------|------|
| 완전 파인튜닝(Full Fine-Tuning) | 모델 전체 가중치 | 매우 큼(고사양 GPU 다수) | 성능 상한이 가장 높음 | 비용·시간 부담, 재앙적 망각 위험 |
| LoRA | 저순위 어댑터만 | 중간(GPU 1~수 대) | 원본 성능 대부분 유지, 배포 가벼움 | 극단적 도메인 전환에는 한계 |
| QLoRA | 4비트 양자화 모델 + 저순위 어댑터 | 작음(GPU 1대) | 접근성 가장 높음 | 양자화로 인한 미세한 정밀도 손실 가능 |
| RAG(검색 증강 생성) | 학습 없음, 외부 문서 검색 | 파인튜닝보다 작음 | 최신 정보 반영 쉬움, 근거 추적 가능 | 모델의 "말투·판단 습관" 자체는 안 바뀜 |

선택 기준은 "모델의 지식 원천을 자주 바꿔야 하면 RAG, 모델의 응답 스타일·판단 패턴을 도메인에 맞게 고정하고 싶으면 LoRA·QLoRA"로 요약할 수 있다.

## 왜 지금 중요한가

기업들이 범용 LLM을 사내 업무에 맞게 커스터마이징하려는 수요가 늘면서 파인튜닝 관련 관심이 높아지고 있다. LoRA·QLoRA는 학습 가능 파라미터를 원본의 0.1% 미만으로 줄이면서도 전체 파인튜닝에 준하는 성능을 보여, 대규모 자본이 없는 기업·연구소에서도 도메인 특화 모델을 만들 수 있게 하는 현실적인 경로로 자리잡았다. ([몬드리안AI 파인튜닝 가이드](https://blog.mondrian.ai/fine-tuning-lora-qlora-guide), [Databricks LoRA 가이드](https://www.databricks.com/kr/blog/efficient-fine-tuning-lora-guide-llms))

프런티어 모델 자체의 파라미터 수와 학습 비용이 계속 커지는 상황에서, 완전 파인튜닝은 소수 빅테크의 전유물이 되어가는 반면 LoRA·QLoRA 계열 기법은 접근 장벽을 낮춰 "누구나 손쉽게 자체 도메인 모델을 만들 수 있는" 환경을 만들고 있다는 진단도 나온다. ([래블업 신정규 대표 세미나 영상](https://www.youtube.com/watch?v=CG7WftCQk9o))

## 회계법인 AI 직무 연결 포인트

회계법인이 범용 LLM을 그대로 쓰면 K-IFRS 계정과목 체계나 감사조서 양식 같은 도메인 특화 용어·서식을 매번 프롬프트로 설명해야 한다. LoRA로 사내 감사조서·회계기준 데이터를 소량 학습시키면, 모델이 이런 서식과 용어를 별도 설명 없이도 일관되게 다루도록 만들 수 있다.

민감한 재무 데이터를 외부 API로 보내기 어려운 보안 요건 때문에, QLoRA로 온프레미스 GPU 한두 대에서 자체 감사 특화 모델을 튜닝해 폐쇄망 안에서 운용하는 접근도 가능하다. 실제로 삼정KPMG의 내부회계관리 AI 솔루션도 "폐쇄망·온프레미스·클라우드" 환경을 모두 지원한다고 밝히고 있어, 이런 경량 미세조정 기법이 활용될 여지가 크다.

또한 세무·감사·회계자문처럼 업무 영역별로 어댑터를 나눠두면, 하나의 기반 모델로 여러 부서의 요구를 동시에 충족시키면서도 배포·관리 비용을 낮출 수 있다.

## 핵심 용어·논쟁

- **어댑터(Adapter)** — 원본 모델은 그대로 두고 옆에 붙여 학습시키는 작은 추가 파라미터 모듈.
- **순위(Rank, r)** — 어댑터 행렬의 크기를 결정하는 값. 작을수록 파라미터 수가 줄지만 표현력도 줄어든다.
- **양자화(Quantization)** — 모델 가중치를 더 적은 비트 수(예: 32비트→4비트)로 표현해 메모리를 줄이는 기법.
- **재앙적 망각(Catastrophic Forgetting)** — 파인튜닝 과정에서 모델이 기존에 잘하던 것을 잊어버리는 현상. 완전 파인튜닝에서 더 두드러진다.
- **PEFT(Parameter-Efficient Fine-Tuning)** — LoRA·QLoRA를 포함해 일부 파라미터만 학습시키는 미세조정 기법을 통칭하는 상위 개념.

성능 상한선에 대해서는 논쟁이 남아 있다. 일부는 LoRA·QLoRA가 완전 파인튜닝과 거의 동등한 성능을 낸다고 보지만, 모델의 지식 자체를 크게 바꿔야 하는 극단적 도메인 전환에서는 여전히 완전 파인튜닝이 필요하다는 반론도 있다.
