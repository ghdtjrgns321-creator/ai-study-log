## 다루는 하위 주제·흐름

```
[1] 문제의식: 왜 MoE인가
     ├─ GPT-4급 파운데이션 모델의 학습·서비스 비용 폭증
     └─ 텍스트·이미지·오디오 등 이질적 데이터를 하나의 밀집 네트워크로 처리하는 데의 한계
        │
[2] MoE의 4대 구성요소
     ├─ 게이팅 함수 — 어떤 전문가를 쓸지 점수 매기고 선택
     ├─ 전문가 네트워크 — 실제 연산을 수행하는 서브 모델
     ├─ 라우팅 전략 — 토큰/모달리티/태스크 등 어느 단위에서 라우팅할지
     └─ 학습·시스템 설계 — 대규모 클러스터에서 안정성·부하 분산 유지
        │
[3] 게이팅 함수 설계
     ├─ 기본형: 선형 계층 + 소프트맥스 + top-K
     │    ├─ top-K를 소프트맥스 이전에 적용 → 빠르지만 확률 해석 어려움
     │    └─ top-K를 소프트맥스 이후에 적용 → 확률 해석 쉽지만 연산 비쌈
     ├─ 비선형/확률적 게이팅: 코사인 유사도 기반 라우팅(온도 파라미터로 집중도 조절)
     └─ 소프트 MoE: 모든 토큰-전문가 쌍에 연속 가중치 부여 → top-K의 불연속성(토큰 버려짐 문제) 회피, 대신 연산량 증가
        │
[4] 아키텍처 배치 위치
     ├─ 트랜스포머의 FFN(피드포워드) 층을 MoE로 대체하는 것이 표준
     │    └─ 이유: FFN이 연산량이 크고, 사전학습된 트랜스포머에서 이미 태스크별 모듈성이 관찰되기 때문
     ├─ 셀프 어텐션은 보통 밀집 형태 유지(토큰 간 연결이 핵심이라 희소화 어려움)
     └─ 예외: 믹스처 오브 어텐션(MoA) — 어텐션 헤드 자체를 전문가로 취급, 스위치헤드·MoH 등 후속 연구 존재
        │
[5] 도메인별 확장
     ├─ 컴퓨터 비전: Convolutional MoE(CMoE) — 국소 패턴 특화 소형 CNN 전문가
     ├─ 비전 트랜스포머: 패치 단위 라우팅(V-MoE의 배치 프라이어리티 라우팅 — 중요 패치부터 전문가 배정)
     └─ 멀티모달: 모달리티 단위 라우팅(UniMoE 등 — 공통 표현 공간 위에 모달리티별 전문가)
        │
[6] 라우팅 세분화 수준
     ├─ 토큰 수준(가장 흔함) — Base Layer 등은 토큰 빈도에 따라 라우팅 폭 조절(희귀 토큰=단일 전문가, 빈번 토큰=다중 전문가)
     ├─ 모달리티 수준 — 데이터 타입별 전문가 풀 분리
     └─ 태스크 수준 — 목적함수·과제별 전문가 특화
        │
[7] 학습·시스템 안정화
     ├─ 보조 손실항으로 전문가 사용 균형 유도 (특정 전문가 과부하/방치 방지)
     ├─ 라우팅 병목이 생기지 않도록 파이프라인 설계
     └─ 디바이스 간 통신 최적화 — "모델 수준 희소성"과 "하드웨어 수준 고밀도 활용"을 동시에 달성하는 게 목표
        │
[8] 학습 패러다임과의 결합
     ├─ 컨티뉴얼 러닝 — 새 태스크를 새 전문가/저활용 전문가에 배정해 파국적 망각 완화
     ├─ 멀티태스크 러닝 — 공유 전문가 + 태스크 전용 전문가 혼합 구조
     └─ 강화학습·연합학습 — 데이터가 비정형/분산된 환경에서 단일 모델 강제 적합의 문제 완화
        │
[9] 결론 및 열린 질문
     ├─ MoE는 "파라미터 규모 확장"과 "이질적 멀티모달 데이터 처리"라는 현대 AI 두 과제를 동시에 겨냥
     └─ 이론 연구는 이제 시작 단계 — 강건성·해석가능성·초대규모 배포 안정성이 향후 과제
```

## 실무 팁·핵심 개념 원문 보존

- MoE 레이어의 4대 구성요소: "게이팅 함수, 전문가 네트워크, 라우팅 전략, 시스템 설계"
- top-K 소프트맥스 순서에 따른 트레이드오프: 소프트맥스 이전 적용(연산 절감, 확률 해석 불가) vs 소프트맥스 이후 적용(확률 해석 가능, 연산 비용 증가).
- 소프트 MoE의 장점: "탑K가 만들어내는 불연속성을 피하게 해준다" — 토큰이 버려지는 문제와 최적화 난이도를 줄임, 대신 전문가당 연산량 증가.
- FFN을 MoE로 대체하는 이유 요약: "FFN 레이어가 연산량이 크고, 이미 많은 유닛이 특정 입력에 활성화되지 않는 식으로 희소하게 동작하기 때문에 희소한 전문가 활성화를 도입하기 자연스러운 위치."

## 불확실 표시

- 영상 속 자동 생성 한국어 자막에 "믹스터 오브스", "MI믹스터" 등 발음 인식 오류로 보이는 표기가 다수 있어, 정확한 논문 용어(Mixture of Experts, Mixture of Attention 등)는 원문 논문(A Comprehensive Survey of Mixture-of-Experts)으로 교차 확인이 필요하다.
- "스위치헤드", "MoH(Mixture of Heads)" 등 어텐션 기반 MoE 후속 연구의 정확한 성능 수치는 자막에서 구체적으로 언급되지 않아, 직접 원 논문 확인이 필요하다.
