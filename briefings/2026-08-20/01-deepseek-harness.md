# 오늘의 AI 개념: 딥시크 하네스(DeepSeek Harness)

> 작성일: 2026-08-20 · 분류: agentic-coding

## 한 줄 정의

딥시크 하네스(DeepSeek Harness, CLI 이름 `dsh`)는 딥시크가 2026년 8월 13일 개발자 프리뷰로 공개하고 MIT 라이선스로 오픈소스화한 에이전트 하네스로, 모델·도구·스킬·세션·샌드박스·저장소·실행 루프·스케줄링·UI까지 에이전트 런타임을 구성하는 거의 모든 요소를 "플러그인"으로 교체할 수 있게 설계됐다.

## 쉬운 설명

운영체제 커널에 모듈을 꽂았다 뺐다 하는 구조를 떠올리면 이해가 쉽다. 대부분의 에이전트 하네스는 모델 선택이나 도구 연결(MCP 서버 등) 정도만 바꿀 수 있고, 세션 관리·샌드박스·UI 같은 핵심부는 벤더가 고정해 놓는다. 딥시크 하네스는 이 핵심부까지 포함해 "everything is a plugin" 철학을 적용했다 — Cordis라는 경량 플러그인 커널 위에서 모델·도구·스킬뿐 아니라 세션 저장 방식, 코드 실행 샌드박스, 파일시스템, 실행 루프, 작업 스케줄링, 심지어 사용자 인터페이스까지 전부 갈아 끼울 수 있는 조각으로 만들었다.

사용법은 단순하다. `npx @deepseek-ai/dsh web` 한 줄로 웹 UI가 `http://127.0.0.1:3080`에서 뜬다. 이 UI에서 새 세션을 만들고 로컬·원격 작업 폴더(워크스페이스)를 지정한 뒤, 어떤 LLM을 백엔드로 쓸지(딥시크 자체 모델뿐 아니라 OpenRouter 등 다른 프로바이더 경유도 가능) 설정 파일이나 UI에서 고를 수 있다.

기존 유사 개념과의 차이는 "모델 중립성의 범위"에 있다. 클로드 코드나 코덱스 같은 코딩 에이전트는 특정 벤더 모델을 중심에 두고 도구 확장에 주로 열려 있는 반면, 딥시크 하네스는 애초에 어떤 모델·어떤 UI든 붙일 수 있는 뼈대만 제공하고 나머지를 커뮤니티 플러그인 생태계에 맡기는 쪽에 가깝다. 다만 이 글을 쓰는 시점 기준 버전은 `0.1.0-rc.5`의 개발자 프리뷰로, 딥시크 스스로도 "호환성이 깨지는 변경이 있을 수 있다"고 명시한 초기 단계다.

## 동작 원리

딥시크 하네스를 구동하는 Cordis 메타프레임워크는 다음 다섯 요소로 이뤄진다.

1. **플러그인 정의** — 모델·도구·UI 등 모든 기능 단위는 함수, 객체, 또는 서비스 클래스 형태의 플러그인으로 작성된다.
2. **컨텍스트(ctx) 저장소** — 모든 플러그인이 공유하는 서비스 저장소로, `ctx.tools`·`ctx.llm`처럼 안정적인 키로 서로의 기능에 접근한다.
3. **의존성 주입(inject)** — 플러그인은 자신이 필요로 하는 다른 플러그인·서비스를 `inject`로 선언해 커널이 자동으로 연결해 준다.
4. **타입화된 이벤트** — 플러그인 간 순서 결정과 관찰(로깅·감사 등)은 정해진 타입을 가진 이벤트를 통해 처리된다.
5. **가역적 등록(reversible effects)** — 플러그인을 마운트할 때 등록한 효과는 언로드 시 안전하게 정리(clean-up)되도록 설계돼, 플러그인을 실행 중에 갈아 끼워도 상태가 꼬이지 않는다.

이 구조 덕분에 이론적으로는 모델 플러그인만 바꿔 다른 LLM으로 전환하거나, 샌드박스 플러그인만 바꿔 실행 환경을 로컬 VM에서 컨테이너로 옮기는 식의 조합이 가능해진다.

## 구체 예시·사례

실제 데모(아래 "자료 깊이 읽기"의 유튜브 영상 기준)에서는 원격 VPS에 이미 `dsh web`을 띄운 상태로, 새 세션에서 "딥시크 하네스용 랜딩페이지를 만들어 달라"고 요청하자 에이전트가 실제로 페이지를 빌드하고, 사용한 스킬·실행 명령어·구동 폴더까지 함께 보여줬다. 대화창에서 "지금 어떤 모델을 쓰고 있냐"고 물으면 OpenRouter를 경유한 `deepseek/deepseek-v4-pro-0813`이라고 명확히 답하는 모델 표시 기능도 확인됐다.

설치는 두 경로다. `npx @deepseek-ai/dsh web`으로 즉시 실행하거나, 저장소를 `git clone`한 뒤 `pnpm install` → `pnpm run build`로 빌드하고 설정 파일에 API 프로바이더(base URL·API 키·모델명)를 적어 넣는 방식이다. 원격 서버에서 띄울 때는 `dsh web --host <도메인> --trust-host` 형태로 접속 도메인을 명시해야 하며, 로컬에서는 이 옵션이 필요 없다.

## 왜 지금 중요한가

딥시크는 하네스 v0.1을 최신 플래그십 모델 V4 프로(V4-Pro-0813, 2026-08-15에 이미 다룸)와 함께 발표했는데, GitHub 저장소는 공개 첫날 기준 스타 약 27,500개·포크 약 2,000개를 기록했고, 공개 나흘째인 8월 17일에는 스타 135,042개·포크 13,592개까지 늘었다. 이 저장소는 딥시크 공식 계정(deepseek-ai) 소유로 직접 확인되며, MIT 라이선스와 "Everything is a Plugin"이라는 README 문구도 실재한다.

다만 "GitHub 역사상 최고 속도"라는 표현은 애그리게이터·블로그 기사에서 반복되고 있을 뿐, GitHub 자체나 딥시크 공식 발표가 이런 순위·기록을 언급한 적은 확인되지 않는다. 스타·포크 수 자체는 실재하는 수치이지만, "역대 최고"라는 프레이밍은 검증되지 않은 과장일 가능성이 있다는 점을 구분해서 봐야 한다. 이 글을 쓰는 시점 기준으로도 저장소 스타 수는 계속 늘고 있어(확인 시점 약 16만 개대), 관심 자체는 꾸준히 유지되고 있다.

## 회계법인 AI 직무 연결 포인트

회계법인이 사내에 AI 에이전트 도구를 도입할 때 가장 먼저 부딪히는 문제는 데이터 주권이다. 클로드 코드·코덱스 같은 폐쇄형 SaaS 에이전트는 감사 증적·클라이언트 재무자료가 외부 벤더 서버를 거치는 구조를 완전히 벗어나기 어렵다. 딥시크 하네스처럼 MIT 라이선스로 소스가 전부 공개되고 샌드박스·저장소 플러그인까지 자체 구현할 수 있는 하네스는, 폐쇄망·온프레미스 환경에서 자체 모델(또는 승인된 프로바이더)만 연결해 감사 자료가 외부로 나가지 않는 사내 에이전트를 구축할 수 있는 선택지를 제공한다.

물론 개발자 프리뷰 단계인 소프트웨어를 감사 업무 워크플로에 바로 투입하는 것은 시기상조다. 하지만 "하네스를 자체 소유·자체 감사할 수 있는가"라는 질문 자체는 이미 회계법인의 AI 거버넌스 논의(2026-08-06에 다룬 PCAOB QC 1000 기반 AI 모니터링·시정, 2026-08-05의 감사위원회 AI 거버넌스 감독 책무 등)와 직결된다. 오픈소스 하네스가 성숙해질수록, 회계법인은 벤더 종속형 SaaS 도구와 자체 호스팅형 오픈소스 하네스 중 어느 쪽이 통제·감사 가능성(auditability) 요건에 더 부합하는지를 실제 조달 의사결정에서 저울질하게 될 가능성이 크다.

또한 "everything is a plugin" 구조는 내부통제 관점에서도 시사점이 있다. 모델·샌드박스·저장소가 각각 독립된 플러그인으로 분리돼 있으면, 어떤 플러그인이 어떤 권한(파일 쓰기, 외부 네트워크 접근 등)을 갖는지 개별적으로 통제·기록하기 쉬워진다. 이는 AI 에이전트 감사증적(2026-07-28에 다룬 EU AI Act 12조·SOX·TACO 통제요건)을 구현할 때, 하나의 거대한 블랙박스 에이전트보다 세분화된 통제점을 설계하는 데 유리할 수 있다.

## 핵심 용어·논쟁

- **Cordis** — 딥시크 하네스를 구동하는 경량 플러그인 커널. 함수·객체·서비스 클래스 형태의 플러그인을 컨텍스트 저장소(ctx)에 등록·해제한다.
- **Everything is a Plugin** — 모델부터 UI까지 에이전트 런타임의 모든 구성요소를 교체 가능한 플러그인으로 다루는 설계 철학.
- **개발자 프리뷰(Developer Preview)** — 정식 출시가 아니라 호환성이 깨질 수 있는 초기 공개 단계. 현재 버전은 `0.1.0-rc.5`.
- **트라젝토리(Trajectory) 뷰** — 세션 내 모든 턴·도구 호출·에이전트 응답을 타임라인으로 추적하는 dsh 고유의 디버깅 기능.

가장 명확히 짚어야 할 논쟁은 "GitHub 역사상 최고 속도"라는 주장의 검증 여부다. 스타·포크 수 자체는 저장소를 직접 열어 확인 가능한 사실이지만, 이를 "역대 최고 기록"으로 부르는 근거는 GitHub도 딥시크도 공식 확인한 바 없다. 신선한 오픈소스 프로젝트가 급성장할 때 애그리게이터 매체가 헤드라인을 부풀리는 전형적 패턴으로 봐야 하며, 실제 채택률·생태계 성숙도는 스타 수만으로 판단하기 어렵다.
