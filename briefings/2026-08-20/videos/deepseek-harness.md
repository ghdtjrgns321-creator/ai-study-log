## 영상 개요

진행자는 딥시크가 막 공개한 오픈소스 에이전트 하네스 dsh를 원격 VPS(가상 사설 서버)에 이미 설치·구동한 상태에서, 웹 UI를 화면 공유로 보여주며 실제 프롬프트 두 개(랜딩페이지 제작, 3D 지구본 제작)를 직접 실행해보고, 마지막에 설치·설정 방법을 별도로 정리해 안내하는 실습형 데모 영상이다.

## 하위 주제별 상세 정리

### 1. 인트로 — GitHub 스타 급증
영상 시작에서 진행자는 딥시크가 dsh(DeepSeek Harness) 플랫폼을 막 출시했다며, 이미 GitHub 저장소가 "약 1시간 만에 23K 스타"를 기록했다고 언급한다(자막 원문: "already 23K stars just in probably one hour"). 이는 진행자 개인이 화면에서 본 수치를 언급한 것으로, 본 브리핑 본문에서 공식적으로 확인한 27,500(첫날)·135,042(4일차) 수치와는 별도의 순간 스냅샷이다 — 정확한 시점별 수치는 직접 재확인이 필요하다.

### 2. 실행 환경 — VPS에서 이미 구동 중
진행자는 로컬이 아니라 원격 가상 사설 서버(virtual private machine)에 dsh 웹 UI를 미리 띄워둔 상태로 데모를 시작한다. 이는 dsh가 로컬 개발 환경뿐 아니라 서버에 상시 배포해 두고 브라우저로 접속하는 방식도 지원한다는 것을 보여준다.

### 3. 새 세션과 워크스페이스
- 새 세션(New Session)을 시작하면 작업 폴더(워크스페이스)를 선택하거나 새로 추가할 수 있다.
- 워크스페이스는 로컬 머신의 폴더뿐 아니라 원격 머신의 폴더도 지정 가능하다.
- 워크스페이스에는 권한(permission)을 부여해야 하며, 진행자는 "쓰기 권한(write permission)"을 부여해야 에이전트가 실제로 해당 폴더에 파일을 쓸 수 있다고 설명한다.

### 4. 실행 모드 선택 (자막 인식 불확실 — 직접 재확인 필요)
자막에는 "s mode, code mode, minimum mode, quer mode" 네 가지로 들리며, 각 모드에 대한 설명 텍스트가 UI에 표시된다고 언급된다. 정확한 모드 명칭(예: Chat 모드/Code 모드/Plan 모드/Query 모드 등으로 추정)은 자동 자막 인식 오류 가능성이 높아 원문 그대로 옮기지 않고, 정확한 이름은 공식 문서나 실제 UI에서 직접 재확인이 필요하다는 점을 표시해 둔다.

### 5. 데모 1 — 랜딩페이지 제작
진행자가 "딥시크 하네스용 랜딩페이지를 만들어줄 수 있어?(can you build a landing page for deepseek harness)"라고 입력하자, 에이전트는 실제로 페이지를 빌드하고 다음을 화면에 함께 보여준다.
- 사용한 스킬(skill)과 실행한 명령(command)
- 완성된 페이지를 로컬에서 띄우려면 어떤 폴더로 이동해 어떤 명령을 실행해야 하는지에 대한 안내
- 완성된 랜딩페이지 결과물 — 진행자는 "매우 깔끔하고 세련되고 프리미엄한 느낌"이라고 평가한다.

### 6. 모델 확인 기능
같은 세션에서 "지금 어떤 모델을 쓰고 있어?"라고 물으면, dsh는 현재 사용 중인 모델을 명확하게 답한다. 진행자의 설정에서는 OpenRouter를 경유한 DeepSeek V4 Pro 0813을 사용 중이었다. 진행자는 이 모델 표시 기능이 유용하다고 강조하는데, 그 이유로 "가끔 자신이 딥시크 모델인지 클로드 모델인지 헷갈리게 답하는" 다른 에이전트 사례를 언급하며, dsh는 이 점에서 명확하다고 설명한다. 또한 딥시크 V4 Pro 0813은 OpenRouter 버전과 별도로 "Infra"라는 다른 프로바이더를 통한 버전도 존재한다고 언급한다(프로바이더명은 자막 인식이 불확실해 직접 재확인 필요).

### 7. 발견된 한계 — 확장형 미리보기 패널 부재
진행자는 dsh 웹 UI를 테스트하면서 "확장 가능한 미리보기 창(expandable preview window)"이 없다는 점을 한계로 지적한다. 즉 에이전트가 웹페이지 등 결과물을 만들어도, 웹 UI 안에서 바로 확인할 방법이 없고 백엔드(가상 사설 머신 또는 로컬호스트) 쪽으로 직접 접속해 확인해야 한다. 실제로 진행자가 에이전트에게 "미리보기 패널이 있냐"고 물었을 때 "패널은 없다"는 답을 받았지만, 에이전트는 대신 백엔드에 웹 서버를 띄워주었다고 설명한다. 로컬 환경에서는 이 서버에 바로 접속할 수 있어 문제없지만, VPS나 리버스 프록시 뒤에 있는 환경에서는 접속이 되지 않을 수 있다는 실무적 주의사항을 짚는다.

### 8. 권한 부여의 유연성
진행자는 워크스페이스에 적절한 권한만 주면 에이전트가 서버에서 원하는 대로 작업을 수행할 수 있다는 점을 편리한 특징으로 꼽는다. 예를 들어 세션에 추가한 워크스페이스 폴더에 쓰기 권한을 주면 그 폴더 안에서 자유롭게 파일을 생성·수정할 수 있다.

### 9. 모델 추가 방법
모델(예: 이 데모에서 쓴 "pter" 모델 — 자막 인식이 불확실해 정식 명칭은 직접 재확인 필요)을 추가하는 방법은 두 가지다.
1. 설정(Settings) 화면의 "Agent Presets and Plugins → Models" 메뉴에서 UI로 추가
2. 설정 파일(configuration file)을 직접 편집해 추가 — 진행자는 이 방식이 "더 편리하다"고 언급한다.

### 10. 데모 2 — 3D 지구본 제작
진행자는 두 번째 세션을 새로 열고 "3D 지구본 데모를 만들어줄 수 있어?(can you build a 3D globe)"라고 요청한다. 에이전트가 작업하는 동안 진행자는 다음 기능을 함께 시연한다.

### 11. 트라젝토리(Trajectory) 뷰 — dsh의 특징적 디버깅 기능
에이전트가 작업하는 도중, 진행자는 해당 세션에서 일어난 모든 일을 순서대로 보여주는 "트라젝토리(trajectory)" 화면을 소개한다.
- 세션 내 모든 턴(turn)과 그 사이의 원인·결과(cause) 관계를 확인할 수 있다.
- 특정 지점을 클릭하면 그 시점에 실제로 무슨 일이 있었는지(사용자 입력, 도구 호출, 에이전트 응답) 상세히 볼 수 있다.
- 세션 로그를 다운로드하거나 검색할 수 있다.
- 타임라인을 클릭해 다니며 시간대별로 무슨 일이 있었는지 확인할 수 있다.
- 진행자는 이 기능이 "다른 인터페이스에서는 거의 없는", dsh만의 독특한 기능이라고 강조하며, 예시로 몇몇 경쟁 제품(자막 인식 불확실 — "클로드 OS"·"오픈 워크"·"코워크" 등으로 들리나 정확한 제품명은 직접 재확인 필요)에는 이런 기능이 없는 것 같다고 언급한다.

### 12. 결과 확인 — 포트 문제와 해결
지구본 작업이 완료됐다는 응답(global.html 생성)을 받고 열어보려 했으나 처음에는 파일을 찾을 수 없었다. 진행자는 포트가 다르게 열렸을 가능성을 확인했고, 실제로 8123번 포트에서 서버가 실행 중임을 발견해 그쪽으로 접속하니 3D 지구본이 정상적으로 로드됐다. 줌인·줌아웃 등 인터랙션도 잘 작동했다고 확인한다.

### 13. 추가 개선 제안 반영
에이전트는 완성 후 "실제 NASA 지구 주간·야간 텍스처 추가", "위도·경도 격자선 추가", "축 라인 추가" 같은 개선 제안을 진행자에게 먼저 제시했고, 진행자가 이를 받아들이자 에이전트가 이어서 작업해 좌표·축 라벨(북/남/동/서)과 텍스처를 반영한 결과물을 완성했다. 텍스처 로딩에 시간이 다소 걸렸지만 최종적으로 NASA Blue Marble 스타일 텍스처가 적용된 지구본이 완성됐다.

### 14. 설정 파일(config file) 작성법
진행자는 영상 후반부에 설정 파일을 통한 구성 방법을 별도로 설명한다.
- 사용할 API를 정의하고, 프로바이더(provider)와 API 키를 지정한다.
- 예시로는 "pter"라는 프로바이더의 base URL을 지정하고, 모델명으로 `deepseek/deepseek-v4-pro-0813` 형태를 사용했다(프로바이더 명칭은 자막 인식이 불확실해 직접 재확인 필요).

### 15. 설치 방법 요약
- 방법 1: `npx`로 즉시 실행.
- 방법 2: 저장소를 `git clone`한 뒤 `pnpm install`, 이어서 `pnpm run build`로 빌드하고, 설정 파일을 위 방식대로 업데이트한 다음 `dsh web`으로 실행.
- 원격 서버(VPS)에서 실행할 때는 접속 도메인을 `--host`로 지정하고 `--trust-host` 옵션을 추가해야 한다고 설명한다(자막에서는 "give it a trust host because I think this is needed"로 언급). 로컬호스트에서 실행할 때는 이 옵션이 필요 없다.

### 16. 마무리
진행자는 3D 지구본 데모가 최종적으로 잘 완성됐다고 정리하며, 전반적으로 "정말 좋은 작업을 했다"고 평가한다. 채널 구독·좋아요·댓글을 유도하며 영상을 마친다.

## 실무 팁 정리 (원문 보존)

- 웹 UI 실행: `npx @deepseek-ai/dsh web`
- 원격 서버 실행 시: 호스트 도메인 지정 + `--trust-host` 옵션 필요(로컬은 불필요)
- 설치(소스 빌드 경로): `git clone` → `pnpm install` → `pnpm run build` → 설정 파일 수정 → `dsh web` 실행
- 워크스페이스에는 쓰기 권한을 명시적으로 부여해야 에이전트가 파일을 생성·수정할 수 있음
- 모델 추가는 설정 UI(Settings → Agent Presets and Plugins → Models) 또는 설정 파일 직접 편집, 두 가지 경로 모두 가능
- 세션 내 모든 작업 이력은 트라젝토리 뷰에서 타임라인 단위로 추적·다운로드·검색 가능

## 자동 자막 인식 불확실 항목 (직접 재확인 필요)

- 실행 모드 4종의 정확한 명칭("s mode/code mode/minimum mode/quer mode"로 자막 인식됨)
- 진행자가 사용한 모델 프로바이더 이름("pter"로 반복 자막 인식됨 — 실제 프로바이더명일 가능성이 있으나 철자 확정 불가)
- 트라젝토리 기능이 없다고 언급된 비교 대상 제품명("클로드 OS/open work/co-work"로 들리는 부분)
