# 오늘의 AI 개념: 매니지드 에이전트(Managed Agents-as-a-Service)

> 작성일: 2026-07-31 · 분류: ai-concept

## 한 줄 정의

매니지드 에이전트는 개발자가 실행 환경을 직접 만들지 않아도 API 호출 한 번으로 코드 실행·웹 탐색이 가능한 자율 에이전트를 격리된 샌드박스에서 바로 받아 쓸 수 있게 해주는 서비스다.

## 쉬운 설명

예전에는 서비스 하나를 돌리려면 서버실을 직접 짓고 전기·냉각까지 관리해야 했다. 클라우드가 등장하면서 API 호출 한 번으로 컴퓨터 한 대가 뚝딱 생기는 방식으로 바뀌었다. 매니지드 에이전트는 이 흐름을 한 단계 더 밀고 나간 것이다 — 컴퓨터 한 대가 아니라 "일할 준비가 된 에이전트 한 마리"를 통째로 빌리는 서비스다.

개발자는 에이전트가 돌아갈 리눅스 샌드박스를 직접 프로비저닝하거나 관리할 필요가 없다. `AGENTS.md`·`SKILL.md` 같은 마크다운 파일로 이 에이전트에게 무엇을 하라고 지시할지만 정의하면, API 호출 한 번으로 격리된 임시 리눅스 환경 안에서 추론·코드 실행·파일 조작·웹 탐색을 수행하는 에이전트가 만들어진다.

기존 에이전트 프레임워크(오케스트레이션 로직을 짜는 오픈소스 라이브러리류)는 "에이전트가 무엇을 할지"는 정의해줬지만 "그 에이전트가 어디서, 어떻게 실행되는지"는 여전히 개발자가 서버·컨테이너를 관리해야 했다. 매니지드 에이전트는 이 실행 인프라 자체를 벤더가 통째로 관리해준다는 점에서 다르다. Google의 경우 이 백엔드를 "Antigravity 하네스"라고 부르는데, 이는 Antigravity IDE(개발자가 직접 쓰는 코딩 도구)와 매니지드 에이전트(API로 호출하는 자율 에이전트) 양쪽을 구동하는 공통 엔진이다.

## 동작 원리

```
① 개발자가 AGENTS.md / SKILL.md로 에이전트의 시스템 지침·스킬 정의
② API 한 번 호출
     → Antigravity 하네스가 에페메랄(임시) 리눅스 샌드박스를 자동 생성
③ 샌드박스 안에서 에이전트가 추론 → 코드 실행 → 파일 조작 → 웹 탐색 수행
     → 이 과정은 "사용자 턴 → 모델 턴"의 단순 대화가 아니라
       "입력 → 툴 호출 → 서브에이전트 호출 → …"가 연속되는 스텝 스트림
④ Interactions API로 세션 상태 유지 → 이후 호출에서 이어서 재개 가능
⑤ 결과 반환, 필요하면 커스텀 매니지드 에이전트로 저장해 재사용·배포
```

기반이 되는 "Interactions API"는 원래 콘텐츠 생성 위주로 설계됐던 기존 API를 에이전트 중심으로 재설계한 것으로, 도구 호출·서브에이전트 호출 같은 중간 단계 전체를 모델과 동등한 일급 구성요소로 다룬다는 점이 특징이다.

## 구체 예시·사례

Google이 공개한 데모에서는 매니지드 에이전트가 Hacker News의 그날 인기 댓글·주제를 읽고 서로 반대되는 두 관점을 골라, 서로 다른 지역에서 전화 연결하는 형식의 3분짜리 라디오쇼 대본으로 재구성한다. 이 과정에서 에이전트는 Gemini 모델로 대본을 쓰고, Lyria로 배경음악을 만들고, Gemini TTS로 음성을 합성하는 세 가지 도구를 스스로 호출했으며, 18개 안팎의 출처를 참고했다. 개발자가 작성한 코드는 API 호출 하나뿐이었다.

## 비슷한 것과 비교

| 구분 | 매니지드 에이전트(Gemini API) | 자체 호스팅 에이전트 프레임워크 | 코딩 에이전트 CLI(Claude Code 등) |
|---|---|---|---|
| 실행 인프라 관리 | 벤더가 샌드박스까지 통째로 관리 | 개발자가 서버·컨테이너 직접 관리 | 로컬 머신 또는 개발자 환경에서 실행 |
| 주 사용처 | 앱에 임베드할 자율 기능(리서치·콘텐츠 생성 등) | 커스텀 오케스트레이션이 필요한 백엔드 시스템 | 개발자 개인의 코딩 작업 보조 |
| 세션 상태 | Interactions API가 관리, 재개 가능 | 직접 설계 필요 | 세션/워크트리 단위로 로컬 관리 |
| 성숙도(2026-07 기준) | Pre-GA(SLA 없음, 프로덕션 비권장) | 성숙도는 프레임워크마다 상이 | 상용 서비스로 안정화 |

선택 기준: 빠르게 프로토타입을 만들거나 인프라 관리 부담을 없애고 싶다면 매니지드 에이전트가, 세밀한 제어와 프로덕션 안정성이 필요하다면 자체 호스팅 프레임워크가 아직은 더 적합하다.

## 왜 지금 중요한가

Google은 2026년 5월 19일 Gemini API 프리뷰로 매니지드 에이전트를 공개했고, Google AI Studio에서 바로 시작할 수 있다. 공식 발표는 Ramp, ResembleAI, Klipy, Stitch 같은 기업이 이미 테스트하고 있다고 밝혔다.

다만 현재 상태는 "Pre-GA(정식 출시 전)" 소프트웨어로, 별도의 SLA(서비스수준협약)나 지원 중단 정책이 적용되지 않으며 프로덕션 환경이나 민감한 데이터에는 사용을 권장하지 않는다는 점이 공식 문서에 명시되어 있다.

- [Introducing Managed Agents in the Gemini API — Google 공식 블로그](https://blog.google/innovation-and-ai/technology/developers-tools/managed-agents-gemini-api/)
- [Agents Overview — Gemini API 공식 문서](https://ai.google.dev/gemini-api/docs/agents)

## 회계법인 AI 직무 연결 포인트

감사 보조 업무(계약서 요약, 이상거래 관련 리서치, 재무제표 초안 검토 프로토타입 등)를 빠르게 시제품으로 만들어볼 때, 인프라를 직접 구축하지 않고 API 호출만으로 자율 에이전트를 붙여 실험해볼 수 있다는 점은 실무 도입 전 개념 검증(PoC) 단계에서 유용하다. 다만 현재는 Pre-GA·민감정보 비권장 상태이므로 실제 감사증거나 고객 재무데이터를 이 서비스에 넣는 것은 시기상조다.

회계법인이 자체 감사 플랫폼(EY Canvas, Omnia 등)에 에이전트 기능을 통합하려 할 때, "에이전트 실행 인프라를 자체 구축할 것인가, 매니지드 서비스에 아웃소싱할 것인가"라는 선택지 자체가 비교 벤치마크가 된다 — 특히 고객 데이터를 외부 벤더의 샌드박스에서 처리해도 되는지는 데이터 거버넌스·기밀유지계약(NDA) 관점에서 반드시 검토해야 할 지점이다.

에이전트가 "어떤 샌드박스에서, 어떤 데이터로, 어떤 도구를 호출했는지"를 기록·추적해야 한다는 요구는 AI 에이전트 감사증적(Audit Trail) 논의와 직접 연결된다. 매니지드 에이전트처럼 실행 환경이 벤더 쪽에 있을수록, 그 실행 로그를 감사인이 어떻게 확보하고 검증할 것인지가 향후 통제 설계의 쟁점이 될 수 있다.

## 핵심 용어·논쟁

- **Antigravity 하네스** — Google의 매니지드 에이전트와 Antigravity IDE를 함께 구동하는 공통 실행 엔진.
- **Interactions API** — 기존 콘텐츠 생성 중심 API를 대체하는, 도구 호출·서브에이전트 호출 등을 모델과 동등하게 다루는 에이전트 중심 API.
- **에페메랄 샌드박스** — 에이전트 실행이 끝나면 사라지는 임시 격리 환경.
- **Pre-GA(Pre-General Availability)** — 정식 출시 전 단계로, SLA나 지원중단 정책이 적용되지 않고 프로덕션·민감데이터 사용이 권장되지 않는 상태.

아직 프리뷰 단계라는 점에서 프로덕션 신뢰성·벤더 종속(lock-in) 우려가 남아 있고, 특히 회계·감사처럼 민감한 데이터를 다루는 업종에서는 데이터가 벤더 관리 샌드박스를 거친다는 사실 자체가 컴플라이언스 검토 대상이 된다는 논쟁이 있다.
