# 오늘의 AI 개념: 커서 컴포저 2.5(Cursor Composer 2.5)

> 작성일: 2026-08-01 · 분류: agentic-coding

## 한 줄 정의

커서 컴포저 2.5는 AI 코딩 도구 회사 커서(Cursor)가 외부 모델에 의존하지 않고 자체적으로 학습시킨 코딩 전용 AI 모델이다.

## 쉬운 설명

지금까지 대부분의 AI 코딩 도구는 앤트로픽·오픈AI 같은 외부 모델 제공사의 두뇌를 빌려 쓰는 방식이었다. 커서도 원래는 그랬다. 컴포저는 커서가 이 두뇌 자체를 직접 만들기 시작했다는 신호다.

비유하면, 지금까지 식당이 다른 농장에서 재료를 사다 요리만 했다면, 컴포저는 그 식당이 직접 밭을 일구기 시작한 셈이다. 재료(모델)를 직접 기르니 자기 요리(코딩 작업)에 맞게 최적화할 수 있고, 남의 밭 사정(외부 모델 회사의 가격 정책·용량 제한)에 덜 휘둘린다.

기존 개념과의 차이는 "누가 모델을 훈련시키는가"에 있다. 코딩 에이전트 프레임워크(예: 오픈소스 오케스트레이션 라이브러리)는 어떤 모델을 어떻게 조합해 쓸지 설계하는 데 집중했지만, 모델 자체를 새로 학습시키지는 않았다. 컴포저는 IDE 회사가 코딩 특화 모델 학습까지 수직계열화했다는 점에서 다른 궤적을 보여준다.

## 동작 원리

```
① 합성 과제 대량 생성
   → 정상 작동하는 저장소에서 기능 하나를 일부러 제거한 "기능 삭제 퍼즐" 등
     컴포저 2 대비 25배 많은 합성 과제로 학습 데이터 확보
② 강화학습(RL) 훈련
   → 테스트 스위트 통과 여부를 검증 신호로 사용해 과제 재구현 능력 강화
③ 텍스트 피드백 기반 국소 보정(Textual-Feedback RL)
   → 기존 방식: 수십만 토큰짜리 전체 작업이 끝난 뒤 "잘했다/못했다" 보상 신호 1개만 줌
   → 개선 방식: 실수가 발생한 지점 바로 옆에 힌트 텍스트를 삽입해
     그 위치에서의 토큰 확률을 온폴리시 증류(on-policy distillation)로 직접 교정
④ 대규모 분산 학습 인프라
   → 샤딩된 뮤온(Muon) 옵티마이저 + 듀얼메시 HSDP로 대형 모델을 0.2초 단위
     옵티마이저 스텝으로 효율적으로 학습
```

핵심은 3번이다. 기존 RL은 결과만 보고 보상을 주는 "결과 기반" 학습이라 원인 지점을 특정하기 어려웠는데, 컴포저 2.5는 실패 지점 근처에 직접 교정 신호를 꽂아 넣어 장시간 작업에서도 궤도를 이탈하지 않도록 만든다.

## 구체 예시·사례

"기능 삭제 퍼즐(feature deletion puzzle)"은 정상 작동하는 저장소에서 특정 기능을 코드에서 통째로 제거한 뒤, 모델에게 기존 테스트 스위트만 주고 그 기능을 처음부터 다시 구현하게 시키는 학습 과제다. 정답(원본 코드)이 이미 존재하므로 사람이 일일이 채점하지 않아도 테스트 통과 여부로 자동 채점할 수 있다. 이런 방식으로 컴포저 2 대비 25배 많은 학습 과제를 확보했다고 커서는 밝혔다.

## 비슷한 것과 비교

| 구분 | 커서 컴포저(자체 모델) | 클로드 코드·코덱스(외부 모델 기반 CLI) | 오픈소스 에이전트 프레임워크 |
|---|---|---|---|
| 모델 소유권 | IDE 회사가 직접 학습 | 모델 제공사(앤트로픽·오픈AI)에 의존 | 특정 모델에 종속되지 않음 |
| 최적화 대상 | 자사 IDE의 실제 사용 패턴에 맞춤 학습 | 범용 모델을 도구로 감쌈 | 오케스트레이션 로직이 핵심 |
| 가격 구조 | 자체 인프라라 저비용 책정 가능 | 모델 제공사 API 가격에 연동 | 사용 모델에 따라 상이 |
| 리스크 | 자체 모델 품질이 시장 기대에 못 미칠 위험 | 외부 모델 가격·정책 변화에 노출 | 성숙도가 프로젝트마다 편차 큼 |

선택 기준: 비용 효율과 장시간 작업 안정성을 우선한다면 컴포저 계열이, 최신 프론티어 모델의 최고 성능 자체를 원한다면 외부 모델 기반 도구가 더 적합하다.

## 왜 지금 중요한가

커서는 2026년 5월 18일 컴포저 2.5를 공개했다. 앤트로픽 클로드 오퍼스 4.7, 오픈AI GPT-5.5와 견줄 프런티어급 코딩 성능을 표방하면서도, 프런티어 모델 대비 대략 10분의 1 가격에 과제를 처리한다고 밝혔다(SWE-Bench Multilingual 벤치마크에서 79.8% 기록, 벤더 자체 발표 수치이며 독립검증은 확인되지 않음).

이 흐름은 커서 한 곳에 국한되지 않는다. AI 코딩 도구 회사가 모델 제공사에 종속되지 않으려 자체 모델 학습에 뛰어드는 것은 코딩 에이전트 시장이 "모델을 빌려 쓰는 단계"에서 "모델을 직접 기르는 단계"로 넘어가고 있다는 신호로 해석할 수 있다.

## 회계법인 AI 직무 연결 포인트

감사법인이 AI 코딩 도구를 내부 개발팀(감사 자동화 스크립트, 데이터 분석 파이프라인 구축 등)에 도입할 때, "어떤 모델을 어떤 방식으로 쓰는 도구인가"를 이해하는 것은 벤더 선정과 비용 예측에 직결된다. 자체 모델 기반 도구는 외부 API 가격 변동 리스크가 적은 대신, 모델 품질을 벤더가 공개한 벤치마크로만 판단해야 하는 한계가 있다.

합성 데이터로 대량의 학습 과제를 만들어 강화학습을 시키는 방식은, 감사·회계 분야에서 라벨링된 실제 사례가 부족한 이상거래 탐지 모델을 학습시킬 때도 응용 가능한 아이디어다 — 정상 거래 패턴을 일부러 변형해 "이상 사례 퍼즐"을 만드는 방식이 유사한 접근이 될 수 있다.

## 핵심 용어·논쟁

- **텍스트 피드백 RL(Textual-Feedback RL)** — 작업 전체가 끝난 뒤 하나의 보상 신호만 주는 대신, 실수가 발생한 지점에 직접 교정 힌트를 삽입해 국소적으로 학습을 유도하는 방식.
- **기능 삭제 퍼즐(Feature Deletion Puzzle)** — 정상 저장소에서 기능을 제거한 뒤 모델이 다시 구현하게 만드는 자동 채점 가능한 합성 학습 과제.
- **온폴리시 증류(On-Policy Distillation)** — 모델이 현재 정책으로 생성한 결과에 대해 실시간으로 교정 신호를 주입해 학습시키는 기법.
- **수직계열화(Vertical Integration)** — IDE·도구 회사가 기반 모델 학습까지 직접 수행하는 것.

자체 모델 학습에 뛰어든 코딩 도구 회사가 벤치마크 수치를 자체 발표한다는 점에서, 독립기관의 검증 없이 수치를 그대로 받아들이는 것은 주의가 필요하다는 지적이 있다.
