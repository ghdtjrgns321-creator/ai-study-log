# 오늘의 AI 개념: OpenAI 코덱스의 GPT-5.6 솔 전환과 멀티에이전트 V2 안정화(Codex GPT-5.6 Sol & Multi-Agent V2)

> 작성일: 2026-07-27 · 분류: agentic-coding

## 한 줄 정의

OpenAI의 에이전틱 코딩 도구 코덱스(Codex)가 최상위 신형 모델 GPT-5.6 솔(Sol)을 전면 도입하면서, 서브에이전트마다 모델·추론 수준·동시성을 따로 지정하는 멀티에이전트 기능이 정식 안정화됐고, 다른 코딩 도구의 설정을 통째로 옮겨오는 가져오기 기능도 넓어졌다.

## 쉬운 설명

GPT-5.6은 OpenAI가 2026년 6월 26일 약 20개 정부 승인 파트너에게만 제한적으로 공개한 프리뷰 모델군이다. 솔(Sol, 최상위)·테라(Terra, 균형)·루나(Luna, 경량) 3단계로 구성되며, 같은 해 7월 9일 일반 사용자에게도 정식 공개(GA)됐다. 코덱스는 이 중 솔을 우선 도입해 코딩 에이전트의 기본 모델로 삼았다.

비유하자면, 기존 코덱스가 "한 명의 작업자에게 모든 일을 맡기는 방식"이었다면, 이번 멀티에이전트 V2(Multi-Agent V2) 안정화는 "팀장이 부하 직원마다 실력(모델)과 업무 강도(추론 수준)를 다르게 배정하고, 몇 명을 동시에 투입할지도 정하는 방식"에 가깝다. 예를 들어 설계는 실력 좋은 상급자에게, 반복 작업은 저비용 신입에게 나눠줄 수 있다.

이 기능은 원래 있었지만 초기 버전에서는 서브에이전트에 지정한 역할(role)이나 모델 설정이 리셋되는 문제가 있었다. 이번에 이 문제가 고쳐지고, 에이전트 탐색(navigation) UI도 개선됐다는 점이 이번 업데이트의 핵심이다.

기존에 이미 다룬 클로드 코드나 GitHub Copilot의 멀티에이전트·모델 선택 기능과 달리, 코덱스의 이번 변화는 "서브에이전트 단위로 모델·추론 수준·동시성을 세밀하게 지정"하는 데 초점이 있고, 동시에 다른 도구(Cursor·Claude Code)의 설정을 옮겨오는 `/import` 기능이 확장됐다는 점이 특징적이다.

## 동작 원리

1. 상위 에이전트가 `spawn_agent` 도구를 호출해 하위(서브) 에이전트를 생성한다. 이때 `agent_type`, `model`, `model_reasoning_effort` 값을 지정할 수 있다.
2. 값을 지정하지 않으면 코덱스가 작업 성격에 맞춰 자동으로 모델을 고른다. 빠른 탐색용 작업엔 저비용 모델(예: gpt-5.6-terra), 난이도 높은 추론엔 고성능 설정을 붙이는 식이다.
3. 이번 안정화(Codex CLI 0.145.0, 2026-07-21)로 서브에이전트에 지정한 역할(role)이 대화 도중 유지되도록 복원됐고, 동시성(몇 개 서브에이전트를 병렬로 띄울지) 설정도 안정적으로 적용된다.
4. 다만 상위 에이전트와 서브에이전트 사이 주고받는 지시문·응답이 암호화되어, 상위 에이전트가 무엇을 지시했는지 로컬에서 그대로 들여다보기 어렵다는 점이 별도 논쟁거리로 남아 있다.
5. `/import` 명령은 Cursor·Claude Code의 설정, MCP 서버 목록, 플러그인, 세션 기록, 커스텀 커맨드, 프로젝트 범위 메모리를 스캔해 코덱스 쪽 형식으로 옮겨온다. API 키 등 민감정보는 보안상 자동 이전되지 않고 재입력이 필요하다.

## 구체 예시·사례

한 팀이 기존에 Claude Code로 만들어 둔 프로젝트 메모리(`CLAUDE.md`)와 MCP 서버 설정, 커스텀 커맨드를 갖고 있다고 하자. 코덱스로 넘어오면서 `/import`를 실행하면, 코덱스가 이 설정들을 스캔해 자동으로 유사한 형태로 옮겨준다. API 키만 새로 입력하면 기존에 쓰던 MCP 연동(예: 사내 DB 조회 서버)을 코덱스에서도 바로 쓸 수 있다.

이렇게 넘어온 프로젝트에서 큰 리팩터링 작업을 맡길 때는, 상위 에이전트에 GPT-5.6 솔 익스트라하이(extra high) 추론 수준을 주고 "레포를 읽고 위험 지점을 파악해 작업을 쪼개라"고 지시한 뒤, 실제 파일 작성·테스트 같은 실행 작업은 루나(Luna) 맥스(Max)처럼 저비용 모델의 서브에이전트 여러 개에 병렬로 분배하는 식의 운용이 실사용자들 사이에서 권장된다.

## 비슷한 것과 비교

| 구분 | OpenAI 코덱스(멀티에이전트 V2) | 클로드 코드(에이전트 팀즈, 기존 브리핑) | GitHub Copilot |
|------|------|------|------|
| 서브에이전트별 모델 지정 | 가능(모델·추론 수준·동시성 개별 설정) | 가능 | 모델 선택기에서 세션 단위 선택 |
| 타 도구 설정 가져오기 | `/import`로 Cursor·Claude Code 설정·MCP·세션 일괄 이전 | 별도 통합 이전 기능은 초점 다름 | 해당 없음 |
| 서브에이전트 지시문 감사 가능성 | 암호화로 로컬 확인 어려움(논쟁 중) | 텍스트·사고 포워딩 옵션 존재(기존 브리핑) | 에이전트 세션 스트리밍으로 로그 확보(기존 브리핑) |

선택 기준: 다른 도구에서 이미 구축한 MCP·메모리 자산을 최소 손실로 옮기려면 코덱스의 `/import`가 유리하고, 위임 과정을 낱낱이 감사해야 하는 규제 산업 워크로드라면 현재 코덱스의 암호화 정책이 걸림돌이 될 수 있다.

## 왜 지금 중요한가

GPT-5.6은 2026년 6월 26일 OpenAI가 정부 승인 파트너 약 20곳에게만 API·코덱스를 통해 제한적으로 공개했고, 7월 9일 전 세계 사용자에게 정식 공개(GA)됐다. 코덱스 개발 총괄 티보 소티오(Thibaut Sottiaux)는 최상위 등급인 솔 울트라(Sol Ultra)를 코덱스 클라이언트에 우선 투입하겠다고 공개적으로 확인했다.

코덱스 공식 체인지로그에 따르면, 2026년 7월 21일 배포된 코덱스 CLI 0.145.0에서 옵트인(선택 적용) 상태였던 멀티에이전트 V2 경험이 안정화됐고, 서브에이전트별 모델 구성, 역할 복원, 개선된 에이전트 탐색이 포함됐다. 같은 배포에서 `/import` 명령이 Cursor·Claude Code의 설정·MCP 서버·플러그인·세션·커맨드·프로젝트 범위 메모리 이전까지 지원하도록 확장됐다.

다만 InfoWorld는 2026년 7월 15일 보도에서, 멀티에이전트 V2가 상위-하위 에이전트 간 지시문을 암호화해 개발자가 위임 과정을 들여다볼 수 없게 됐고, 금융·의료 등 규제 산업 기업들이 "AI 시스템이 무엇을 왜 했는지 증명"하기 어려워 미션 크리티컬 업무 배포를 미룰 수 있다고 지적했다.

## 회계법인 AI 직무 연결 포인트

회계법인이 감사·재무 데이터 처리 파이프라인을 코딩 에이전트로 자동화한다면, 서브에이전트별로 모델과 권한을 분리하는 이번 멀티에이전트 V2 방식은 "설계·검토는 고성능 모델, 반복 데이터 정제는 저비용 모델"처럼 업무를 역할별로 나누는 내부통제 설계에 참고가 된다. 다만 InfoWorld가 지적한 지시문 암호화 문제는 그대로 감사 리스크가 된다.

감사 실무에서는 "AI가 어떤 지시를 받아 어떤 산출물을 만들었는지" 추적 가능성(traceability)이 내부통제 평가의 핵심 항목인데, 상위 에이전트가 서브에이전트에게 내린 지시문이 로컬에서 암호화되어 확인이 어렵다면, 이 부분을 통제 미비점(control deficiency)으로 문서화하거나 벤더에 감사 로그 API 제공을 요구해야 하는 상황이 생길 수 있다.

또한 `/import`처럼 다른 도구의 MCP 서버·세션·메모리를 이관하는 기능은, 회계법인이 여러 벤더의 AI 코딩 도구를 병행 평가하거나 교체할 때 발생하는 "설정 자산 이전 리스크"를 낮춰준다는 점에서, 벤더 종속성(vendor lock-in)을 낮추는 조달 전략 논의에 실제 사례로 인용할 수 있다.

## 핵심 용어·논쟁

- 멀티에이전트 V2(Multi-Agent V2): 상위 에이전트가 서브에이전트를 생성해 모델·추론 수준·동시성을 개별 지정하는 코덱스의 오케스트레이션 방식.
- 리즈닝 이펙트(Reasoning Effort): 같은 모델 티어 안에서 얼마나 깊이 생각하게 할지(light~extra high, ultra)를 정하는 다이얼.
- `/import`: Cursor·Claude Code의 설정·MCP 서버·플러그인·세션·커맨드·프로젝트 메모리를 코덱스로 옮기는 마이그레이션 명령.
- 서브에이전트 지시문 암호화: 상위-하위 에이전트 간 통신을 암호화해 응답만 복호화 가능하게 한 정책으로, 감사 추적성 논쟁의 핵심 쟁점.
- 쟁점: 위임 과정 암호화는 프롬프트 유출·조작 방지에는 도움이 되지만, 규제 산업의 "AI 행위 증명" 요구와는 정면으로 충돌한다는 점이 현재 개발자 커뮤니티의 핵심 논쟁이다.

## 자가 점검 질문
