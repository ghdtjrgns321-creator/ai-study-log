# 오늘의 AI 개념: 프로그래매틱 툴콜링(Programmatic Tool Calling, PTC)

> 작성일: 2026-08-17 · 분류: ai-concept

## 한 줄 정의

LLM이 도구를 하나씩 호출할 때마다 모델을 왕복(round-trip)하는 기존 JSON 함수 호출 방식 대신, 코드 실행 컨테이너 안에서 여러 도구 호출을 엮은 코드를 직접 작성·실행해 필요한 결과만 압축해 돌려받는 방식이다.

## 쉬운 설명

기존 방식(JSON 툴콜링)은 비서에게 "A 확인해줘", "B 확인해줘", "C 확인해줘"를 매번 따로 지시하고 그때마다 결과를 다 받아보는 것과 같다. 확인할 항목이 20개면 왕복이 20번 생기고, 매번 받은 원자료가 전부 비서의 메모장(컨텍스트 창)에 쌓인다.

프로그래매틱 툴콜링은 "이 스크립트대로 20개를 한 번에 조회하고, 기준을 넘는 것만 추려서 보고해줘"라고 코드로 지시하는 것에 가깝다. 도구 호출과 그 결과 처리(필터링·집계)가 모델 바깥의 코드 실행 환경 안에서 한 번에 끝나고, 모델에게는 최종적으로 필요한 요약만 전달된다.

기존의 "코드 실행 도구(code execution tool)" 자체와 다른 점은, 단순히 모델이 계산용 코드를 실행하는 것을 넘어 그 코드 안에서 다른 도구(데이터베이스 조회, 사내 API 등)를 직접 호출할 수 있다는 것이다. 즉 코드 실행과 도구 호출이 하나의 턴(turn) 안에서 결합된다.

## 동작 원리

1. 도구 정의에 `allowed_callers: ["code_execution_20260120"]`를 추가해, 해당 도구를 코드 실행 컨테이너 안에서 호출 가능하도록 지정한다.
2. 사용자가 복합 요청(예: "서부·동부·중부 지역 매출을 조회해 어디가 가장 높은지 알려줘")을 보내면, 모델은 개별 도구 호출을 직접 하는 대신 이를 조합하는 코드를 작성한다.
3. 이 코드가 코드 실행 컨테이너 안에서 실행되면서, 그 안에서 `query_database` 같은 도구가 여러 번 호출되고 결과가 즉시 필터링·가공된다.
4. 원자료(수백 KB 단위의 조회 결과)는 컨테이너 안에만 머물고, 모델의 컨텍스트 창에는 코드 실행 결과로 압축된 최종 값만 전달된다.
5. 이 덕분에 모델-도구 사이의 왕복 횟수가 줄고, 컨텍스트에 쌓이는 토큰 양도 함께 준다.

```python
tools=[
    {"type": "code_execution_20260120", "name": "code_execution"},
    {
        "name": "query_database",
        "description": "Execute a SQL query against the sales database.",
        "input_schema": {"type": "object", "properties": {"sql": {"type": "string"}}, "required": ["sql"]},
        "allowed_callers": ["code_execution_20260120"],
    },
]
```

## 구체 예시·사례

직원 20명의 경비 한도 초과 여부를 확인한다고 하자. 기존 JSON 툴콜링에서는 모델이 직원마다 "이 사람 경비 내역 조회해줘"를 20번 요청하고, 그때마다 수천 건의 경비 라인 항목이 통째로 모델 컨텍스트에 들어온다. 프로그래매틱 툴콜링에서는 모델이 20명 전체를 순회하며 조회·합산·한도 비교까지 하는 스크립트 하나를 작성해 코드 실행 컨테이너에서 돌리고, 한도를 초과한 직원 명단만 최종 결과로 받는다. Anthropic 공식 문서는 이 경우 모델이 처리해야 할 정보량이 수백 KB에서 몇 줄로 줄어든다고 설명한다.

실제 효과는 벤치마크로도 확인된다. Anthropic이 BrowseComp·DeepSearchQA(다단계 웹 리서치·복합 정보검색 벤치마크)에서 기본 검색 도구 위에 프로그래매틱 툴콜링을 얹었을 때, 평균 11% 성능 향상과 24% 적은 입력 토큰 사용을 관찰했다고 밝혔다.

## 비슷한 것과 비교

| 구분 | JSON 툴콜링(기존) | 프로그래매틱 툴콜링(PTC) |
|---|---|---|
| 호출 방식 | 모델이 매번 JSON으로 도구 하나씩 호출 | 모델이 코드를 작성해 여러 도구를 한 번에 조합 |
| 왕복 횟수 | 도구 호출 수만큼 모델 왕복 발생 | 코드 실행 1턴 안에서 여러 호출 처리 |
| 컨텍스트 소비 | 원자료가 그대로 컨텍스트에 누적 | 컨테이너 안에서 필터링 후 요약만 전달 |
| 병렬·팬아웃 처리 | 순차 호출에 취약 | arXiv 2608.06370 기준 14개 모델 중 13개에서 병렬 팬아웃 우세 |
| 적합한 상황 | 도구 호출이 1~2회로 단순한 경우 | 다단계·반복 조회, 대량 원자료 필터링이 필요한 경우 |

선택 기준을 한 줄로 정리하면: 도구 호출이 몇 번 안 되면 JSON 툴콜링으로 충분하지만, 여러 항목을 반복 조회하거나 원자료가 크고 요약만 필요하다면 프로그래매틱 툴콜링이 왕복·토큰 비용을 실질적으로 줄인다.

## 왜 지금 중요한가

- Anthropic은 프로그래매틱 툴콜링을 2025년 11월 20일 베타(`advanced-tool-use-2025-11-20` 헤더)로 출시했고, 이후 Advisor Strategy·Tool Search 등과 함께 "Advanced Tool Use" 플랫폼으로 확장했다. [Programmatic tool calling — Claude Platform Docs](https://platform.claude.com/docs/en/agents-and-tools/tool-use/programmatic-tool-calling)
- 2026년 8월 6일 공개된 독립 연구 "The Bitter Lesson of Tool Calling"(arXiv 2608.06370)은 GPT-5.6 계열을 포함한 14개 모델을 BFCL v4 벤치마크로 비교해, 11개 모델에서 PTC가 JSON 툴콜링과 동등하거나 우수했고 GPT-5.6 계열은 10.6% 개선됐다고 보고했다. 이는 이 패턴이 특정 벤더에 국한되지 않고 일반화된다는 최초의 체계적 실증이라는 점에서 의미가 있다. [The Bitter Lesson of Tool Calling](https://arxiv.org/abs/2608.06370)
- 같은 연구는 컨텍스트가 길어져 성능이 떨어지는 "컨텍스트 로트(context rot)" 상황에서 기존 JSON 방식이 평균 2.3% 성능 저하를 보인 반면, PTC는 안정적이었다고 밝혔다.

## 회계법인 AI 직무 연결 포인트

감사·내부회계관리제도(ICFR) 평가에서는 다수 계정·거래·통제 항목을 반복 조회한 뒤 예외만 추려 보고하는 작업이 많다. 예를 들어 200개 매출채권 계정의 회수 지연 여부를 하나씩 조회하는 대신, 프로그래매틱 툴콜링으로 한 번에 조회·집계해 예외 항목만 보고받는 식으로 워크플로우를 설계하면 모델 왕복과 토큰 비용을 크게 줄일 수 있다. 이는 앞서 다룬 KPMG AI SOX 솔루션류의 "모집단 추출부터 예외 판별까지 AI 에이전트가 수행"하는 아키텍처의 기술적 기반과도 맞닿아 있다.

다만 코드가 실행 컨테이너 안에서 자동으로 도구를 호출·조합한다는 것은 감사증적 관점에서 새로운 통제 포인트이기도 하다. 어떤 코드가 어떤 도구를 어떤 인자로 호출했는지, 컨테이너 안에서 어떤 필터링 로직이 적용됐는지를 로그로 남기고 검토할 수 있어야, "AI가 만든 증거도 사람이 신뢰성을 검증해야 한다"는 감사 원칙을 지킬 수 있다.

## 핵심 용어·논쟁

- 코드 실행 컨테이너(Code Execution Container): 모델이 작성한 코드가 격리된 환경에서 실행되는 공간으로, 프로그래매틱 툴콜링은 이 컨테이너 안에서 도구를 호출한다.
- `allowed_callers` 필드: 특정 도구를 코드 실행 컨테이너 안에서 호출 가능하도록 명시적으로 허용하는 도구 정의 필드.
- BFCL v4(Berkeley Function-Calling Leaderboard v4): 도구 호출 능력을 평가하는 표준 벤치마크로, 이번 연구의 핵심 비교 기준이다.
- 컨텍스트 로트(Context Rot): 컨텍스트 창에 정보가 쌓일수록 모델 성능이 저하되는 현상으로, 앞서 다룬 개념이다.
- 논쟁 지점: 모델에게 코드 실행 권한을 준다는 것 자체가 샌드박스 탈출·의도치 않은 데이터 유출 같은 새로운 보안 표면을 여는 것이라는 우려가 있으며, Anthropic도 관련 엔지니어링 문서에서 이 비용을 함께 설명한다.

## 자료 깊이 읽기

### Programmatic tool calling — Claude Platform Docs(Anthropic 공식 문서) — 영어/공식 기술문서/중급
Anthropic의 공식 개발자 문서로, 프로그래매틱 툴콜링의 동작 방식과 `allowed_callers` 필드 사용법, 지원 모델 목록(Claude Opus 5·Sonnet 5·Fable 5·Mythos 5 등), 20명 직원 경비 조회 예시, BrowseComp·DeepSearchQA에서의 11% 성능 향상·24% 토큰 절감 수치를 담고 있다. 코드 실행 도구가 활성화돼 있어야 하며, ZDR(제로 데이터 보관) 적용 방식도 별도로 안내한다.

### The Bitter Lesson of Tool Calling(arXiv 2608.06370) — 영어/학술 논문/중상급
2026년 8월 6일 공개된 논문으로, Ishan Patel 등 4인이 14개 언어모델을 BFCL v4로 비교해 프로그래매틱 툴콜링이 JSON 툴콜링 대비 11개 모델에서 동등 이상, GPT-5.6 계열에서 10.6% 개선, 병렬 팬아웃 상황에서 14개 중 13개 모델 우세, 컨텍스트 로트 상황에서 안정적임을 실증했다. Anthropic이 자체 문서로 주장한 이점이 벤더 중립적으로 재현된다는 점에서, 이 패턴이 Claude 전용 트릭을 넘어 업계 공통 방향으로 자리잡고 있음을 보여준다.
