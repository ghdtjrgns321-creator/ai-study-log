# 오늘의 AI 개념: 클로드 코드 셀프호스티드 실행환경(Claude Code Self-Hosted Environments)

> 작성일: 2026-08-17 · 분류: agentic-coding

## 한 줄 정의

Claude Code의 웹·모바일·데스크톱·예약 루틴 세션을 Anthropic의 클라우드가 아니라 조직이 직접 운영하는 서버("러너")에서 실행하도록 해주는 기능으로, 2026년 8월 6일 Team·Enterprise 플랜 대상 공개 베타로 출시됐다.

## 쉬운 설명

지금까지 Claude Code를 웹·모바일에서 쓰면 세션이 실제로 실행되는 컴퓨트는 전부 Anthropic이 관리하는 인프라였다. 셀프호스티드 실행환경은 이 실행 계층만 떼어내 회사 내부망 서버나 컨테이너로 옮기는 기능이다.

비유하면 이렇다 — 지금까지는 택배(코드 실행)를 전부 택배회사(Anthropic) 창고에서 포장·발송했다면, 이제는 회사가 직접 운영하는 물류창고(자체 서버)에서 포장하고, 다만 배송 지시서(프롬프트·응답)는 여전히 택배회사 시스템을 거쳐 전달되는 구조다. 즉 "완전한 온프레미스"가 아니라 실행 계층만 이전하는 하이브리드 모델이라는 점이 핵심이다.

기존에도 Remote Control이라는 기능으로 세션을 특정 개인 머신에 묶어둘 수 있었지만, 이는 각자의 노트북·서버에 세션이 고정되는 개인용 방식이었다. 셀프호스티드 실행환경은 플랫폼팀이 운영하는 공유 인프라(고정 러너 여러 대, 또는 필요할 때만 뜨는 온디맨드 러너)에 세션을 분산 배치한다는 점에서 다르다.

## 동작 원리

1. 조직 관리자가 claude.ai 관리자 설정에서 "Cloud environments" 페이지에 새 환경을 만들고, 1회만 노출되는 "환경 시크릿"(`ccpool_...` ID, 생성 후 365일 만료)을 발급받는다.
2. 러너를 띄울 리눅스/macOS 호스트(윈도우 미지원)에 Claude Code v2.1.224 이상을 설치하고, 시크릿 파일을 `/etc/claude/environment-secret` 등에 저장한다.
3. `claude self-hosted-runner --environment-secret-file '<경로>' --base-dir '<쓰기가능한 경로>'` 명령으로 러너를 실행하면, 러너가 환경에 등록되고 작업을 폴링(polling)하기 시작한다.
4. claude.ai/code에서 세션을 시작할 때 환경 선택기에서 이 셀프호스티드 환경을 고르면, 다음으로 폴링에 걸린 러너가 세션을 집어가(`Picked up session <id>` 로그) 저장소를 클론하고 격리된 체크아웃 디렉터리에서 작업을 수행한다.
5. 세션 중 생성된 코드·빌드 산출물·시크릿은 러너가 있는 조직 인프라에 남지만, 프롬프트·모델 응답·도구 실행 결과(Claude가 읽은 코드 포함)·세션 트랜스크립트는 추론과 웹/모바일/데스크톱 간 세션 연속성을 위해 여전히 Anthropic으로 전송된다.
6. 다른 머신에서도 `claude -p "메시지" --cloud <세션ID>` 명령으로 실행 중인 세션에 후속 지시를 보낼 수 있다.

## 구체 예시·사례

한 회계법인의 플랫폼팀이 사내 ERP 연동 코드를 Claude Code로 작업하되, 소스코드가 사내망 밖으로 나가지 않아야 한다고 가정하자. 관리자는 "Cloud environments"에서 환경을 만들고 시크릿을 발급한 뒤, 사내 VPC 안의 리눅스 서버에서 `claude self-hosted-runner --environment-secret-file /etc/claude/environment-secret --base-dir /workspace`를 실행해 러너를 상시 대기시킨다. 개발자가 claude.ai/code에서 이 환경을 선택해 사내 GitHub 저장소로 세션을 시작하면, 러너가 이미 사내망에서 접근 가능한 자격증명으로 저장소를 클론해 격리된 디렉터리에서 코드를 체크아웃·수정한다. 이때 소스코드 체크아웃과 빌드 산출물은 사내 서버에 남지만, Claude가 그 코드를 읽고 생성한 응답·툴 실행 로그는 추론을 위해 Anthropic으로 전송된다는 점을 거버넌스 문서에 명시해야 한다.

## 비슷한 것과 비교

| 구분 | Anthropic 호스팅(기본) | Remote Control | 셀프호스티드 실행환경 |
|---|---|---|---|
| 실행 인프라 | Anthropic 클라우드 | 사용자 개인 머신 | 조직이 운영하는 서버·컨테이너(공유) |
| 운영 주체 | Anthropic | 개인 개발자 | 플랫폼팀(관리자) |
| 코드·시크릿 보관 위치 | Anthropic 인프라 | 개인 머신 | 조직 인프라 |
| 프롬프트·응답 전송 여부 | Anthropic으로 전송 | Anthropic으로 전송 | 동일하게 Anthropic으로 전송(변화 없음) |
| 적합한 대상 | 대부분의 조직(운영 단순성) | 개인 워크스테이션 기반 작업 | 내부망 접근·컴플라이언스 요구가 있는 팀 |

선택 기준을 한 줄로 요약하면: 사내망 안의 시스템에 접근하거나 코드·시크릿이 외부로 나가면 안 되는 요건이 있을 때만 셀프호스티드를 고려하고, 그렇지 않다면 Anthropic 공식 문서도 권장하듯 운영 부담이 적은 기본 호스팅을 쓰는 편이 낫다.

## 왜 지금 중요한가

- Anthropic은 2026년 8월 6일 Team·Enterprise 플랜을 대상으로 셀프호스티드 실행환경 공개 베타를 열었다고 공식 블로그에서 밝혔다. [Self-hosted environments for Claude Code](https://claude.com/blog/run-claude-code-sessions-on-your-own-compute)
- 공식 문서는 이 기능이 기본적으로 꺼져 있고, ZDR(Zero Data Retention) 조직에는 제공되지 않는다고 명시한다 — 즉 "완전한 데이터 미보관"과는 별개의 기능이다. [Self-hosted environments quickstart](https://code.claude.com/docs/en/self-hosted-environments-quickstart)
- 설정에는 러너를 상시 운영할 엔지니어링 리소스가 필요하다고 공식 문서가 밝히고 있어, 도입 전 운영 부담을 따져야 한다.

## 회계법인 AI 직무 연결 포인트

회계법인·감사대상 기업이 내부 재무시스템·ERP와 연동된 코드를 AI 에이전트로 작업할 때 가장 먼저 부딪히는 질문이 "소스코드와 자격증명이 우리 통제 범위를 벗어나는가"이다. 셀프호스티드 실행환경은 코드 체크아웃·빌드 산출물·시크릿을 조직 인프라에 묶어둠으로써 이 우려의 상당 부분을 해소하지만, 프롬프트와 모델 응답 자체는 여전히 Anthropic으로 전송된다는 점은 정확히 이해해야 한다. AI 거버넌스 담당자가 이 기능 도입을 검토할 때는 "어떤 데이터가 실제로 사내에 남고, 어떤 데이터가 외부로 나가는가"를 구분해 통제 설계 문서에 반영하는 역량이 필요하다.

또한 이 기능은 감사대상회사의 IT 일반통제(ITGC) 평가 관점에서도 새로운 검토 항목이 된다. 러너가 사내망의 어떤 시스템에 접근 권한을 갖는지, 환경 시크릿 발급·폐기 절차가 적절한지, 세션 격리가 실제로 지켜지는지를 감사인이 이해하고 질문할 수 있어야 클라이언트의 AI 에이전트 도입을 평가할 수 있다.

## 핵심 용어·논쟁

- 러너(Runner): 환경에 등록되어 세션 작업을 폴링·실행하는 장기 실행 프로세스. 고정(fixed) 모드와 필요 시 자동으로 뜨고 내려가는 온디맨드(on-demand) 모드가 있다.
- 환경 시크릿(Environment Secret): 러너가 환경에 인증하는 데 쓰는 1회 노출 값으로, 365일 후 만료되며 유출 시 회전(rotate)해야 한다.
- ZDR(Zero Data Retention): Anthropic이 트랜스크립트를 보관하지 않는 별도 계약 옵션으로, 셀프호스티드 실행환경과는 함께 쓸 수 없다.
- 논쟁 지점: 이 기능이 "온프레미스"로 소개되기 쉽지만 실제로는 프롬프트·응답·툴 결과가 여전히 Anthropic으로 전송되는 하이브리드 구조라, 완전한 데이터 격리를 기대한 조직에는 오해의 소지가 있다는 지적이 나온다.

## 자료 깊이 읽기

### Self-hosted environments for Claude Code(Anthropic 공식 블로그) — 영어/공식 발표/중급
Anthropic이 2026년 8월 6일 공개한 발표문으로, 셀프호스티드 실행환경의 배경과 데이터 처리 원칙을 설명한다. 저장소 체크아웃·빌드 산출물·시크릿·세션 중 생성 파일은 조직 인프라에 남지만, 프롬프트·응답·툴 결과·트랜스크립트는 여전히 Anthropic으로 전송된다는 점을 분명히 한다. Team·Enterprise 플랜에서 기본 꺼짐 상태로 제공되며, 조직이 내부 서비스·툴체인·보안 통제 옆에서 세션을 돌릴 수 있다는 점을 핵심 가치로 제시한다.

### Self-hosted environments quickstart(Anthropic 공식 문서) — 영어/공식 기술문서/중상급
환경 생성부터 러너 실행, 세션 라우팅까지 실제 명령어 단위로 안내하는 공식 퀵스타트다. `claude self-hosted-runner --environment-secret-file --base-dir` 명령, 환경 시크릿의 365일 만료·회전 절차, 러너가 등록되지 않을 때의 트러블슈팅, `claude -p "메시지" --cloud <세션ID>`로 다른 머신에서 후속 지시를 보내는 방법까지 구체적으로 다룬다. 프로덕션 배포 시에는 별도 문서(Deploy to production)에서 오케스트레이터 기반 러너 재시작, git 자격증명 구성, 네트워크 요건을 다룬다고 안내한다.
