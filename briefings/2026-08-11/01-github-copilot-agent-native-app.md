# 오늘의 AI 개념: 깃허브 코파일럿 앱(GitHub Copilot App)의 에이전트 네이티브 데스크톱 경험

> 작성일: 2026-08-11 · 분류: agentic-coding

## 한 줄 정의

깃허브 코파일럿 앱은 코드 한 줄씩 제안하던 기존 코파일럿을, 여러 작업을 동시에 에이전트에 맡기고 진행 상황을 한곳에서 관리하는 프로젝트 관제탑 형태의 데스크톱 애플리케이션으로 바꾼 것이다.

## 쉬운 설명

기존 코파일럿이 옆에서 코드를 거들어주는 조수 한 명이었다면, 새 앱은 여러 조수(에이전트)에게 각자 다른 업무를 맡기고 진행판에서 한눈에 훑어보는 상황실에 가깝다. "My Work"라는 통합 화면에서 지금 돌고 있는 에이전트 세션, 이슈, PR(풀 리퀘스트), 자동화 작업을 한 번에 확인한다.

각 세션은 독립된 깃 워크트리(git worktree, 같은 저장소의 별도 작업 사본)에서 실행돼 여러 에이전트가 동시에 일해도 서로 코드를 덮어쓰지 않는다. 작업은 클라우드의 격리된 리눅스 환경이나 로컬 컴퓨터의 격리 환경 중 골라 돌릴 수 있다.

기존 IDE 내장형 코파일럿(코드 제안 한 줄 단위)과 다르게, 이번 앱은 IDE 밖에서 여러 에이전트 세션을 동시에 조율하는 별도 관리 레이어라는 점이 핵심 차이다. 깃허브 고유의 이슈·PR·CI(지속적 통합) 데이터와 결합했다는 점도 다른 도구와 구분되는 지점이다.

## 동작 원리

1. 사용자가 "My Work" 화면에서 이슈나 작업을 에이전트에 할당한다.
2. 에이전트는 클라우드 또는 로컬 샌드박스 안에 독립 워크트리를 만들어 작업을 시작한다.
3. Canvas 화면에서 계획, 터미널 출력, 배포 상태를 실시간으로 보여주고 사용자가 중간에 개입할 수 있다.
4. 코드 리뷰 단계에서 Medium Tier Review(고성능 모델 리뷰), `/security-review`(보안 중심 점검), `/rubber-duck`(다른 모델의 반대 의견) 같은 스킬로 자체 검증한다.
5. Agent Merge가 CI 결과·필수 리뷰어·병합 조건을 계속 지켜보다가 조건이 채워지면 병합까지 자동 처리한다.
6. 반복 작업은 Cloud Automations로 예약하거나 깃허브 이벤트에 반응하도록 설정하고, `/chronicle` 명령으로 기기를 옮겨도 세션 맥락을 이어간다.

## 구체 예시·사례

개발자가 "의존성 라이브러리를 최신 버전으로 올리고 깨지는 테스트를 고쳐라"는 이슈를 `/autopilot`에 할당한다고 하자. 에이전트는 클라우드 샌드박스에 별도 워크트리를 만들어 의존성을 올리고 테스트를 돌린 뒤, 실패한 테스트를 분석해 코드를 수정한다. 이어 `/rubber-duck`으로 다른 모델에게 변경 사항을 재검증받고 PR을 연다. Agent Merge는 자동 코드리뷰 통과 여부와 CI 결과를 계속 지켜보다 조건이 모두 채워지면 병합까지 마무리한다. 그동안 개발자는 다른 이슈에 곧바로 착수할 수 있다.

## 비슷한 것과 비교

| 항목 | 깃허브 코파일럿 앱 | Claude Code | Cursor(v3.11) |
|---|---|---|---|
| 기본 축 | 깃허브 이슈·PR·CI 데이터 통합 관제 | 터미널 기반 에이전틱 코딩 하네스 | 에디터 내장 다중 대화(Side Chats) |
| 병렬 작업 방식 | 세션별 독립 워크트리 + 클라우드·로컬 샌드박스 | 서브에이전트·백그라운드 세션 | Side Chats(파생 대화, 메인 스레드에 재합류 가능) |
| 병합·배포 자동화 | Agent Merge가 리뷰·CI 조건 충족 시 자동 병합 | 사용자가 훅으로 직접 구성 | 없음(에이전트가 PR 생성까지만) |

선택 기준: 깃허브 이슈·PR 흐름을 중심으로 여러 작업을 동시에 굴리고 병합까지 자동화하려면 코파일럿 앱, 터미널에서 깊이 있는 단일 작업에 집중하려면 Claude Code, 에디터 안에서 대화형으로 여러 갈래를 실험하려면 Cursor가 맞다.

## 회계법인 AI 직무 연결 포인트

회계법인 내부 IT·데이터팀이 감사 자동화 스크립트나 사내 도구를 자체 개발할 때, 이슈 등록만으로 반복 유지보수(라이브러리 업데이트, 버그 수정)를 에이전트에 맡기고 Agent Merge로 승인 절차까지 자동화하면 소규모 개발 인력으로도 감사 지원 도구를 지속적으로 유지보수할 수 있다.

클라우드·로컬 샌드박스 선택권은 민감한 회계 데이터를 다루는 내부 도구를 개발할 때, 로컬 격리 환경에서만 에이전트를 돌리도록 중앙 정책으로 강제할 수 있어 데이터 반출 우려를 줄이는 데 활용할 수 있다. `/security-review` 같은 내장 스킬은 사내 AI 도구 자체의 보안 취약점을 코드 리뷰 단계에서 자동 점검하는 데 쓸 수 있어, AI 거버넌스 체크리스트의 한 항목으로 편입할 수 있다.

## 핵심 용어·논쟁

- Canvas — 에이전트의 계획·PR·터미널·배포 상태를 한 화면에서 보여주는 협업 인터페이스.
- Agent Merge — CI 모니터링부터 필수 리뷰어 추적, 실패 체크 해결, 병합 조건 관리까지 자동화하는 기능.
- 워크트리(Worktree) — 하나의 깃 저장소에서 여러 작업 디렉터리를 동시에 만들어 세션 간 충돌 없이 병렬 작업하게 하는 깃 기능.
- Memory++ / `/chronicle` — 여러 기기·세션 간 작업 맥락을 이어주는 기능.
