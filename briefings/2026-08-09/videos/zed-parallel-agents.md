- 채널/형식: Zed 공식 채널 — 기능 소개 데모 영상(2026년 4월 23일 게시)

- 출처 확인: yt-dlp로 영어 자막을 직접 내려받아 전체 구간을 확인했다.

## 다루는 흐름

```
[1] 새 에이전트 사이드바 소개
     └─ 외부 에이전트(Claude Code, Codex, Amp, Cursor, Open Code) 스레드 임포트
        │
[2] 프로젝트 열기 → 새 스레드 생성
     ├─ 전체화면 모드로 에이전트에 집중
     └─ 첫 스레드: 제드 자체 에이전트에게 "README 기반 프로젝트 설명" 요청
        │
[3] 병렬로 두 번째·세 번째 스레드 추가
     ├─ 두 번째: 클로드 에이전트 — 같은 질문 반복
     └─ 세 번째: 커서 에이전트 — 같은 질문 반복
        │  (세 스레드가 동시에 실행되며, 완료 시 파란 점 → 에이전트 아이콘으로 전환)
        │
[4] 레이아웃 커스터마이징
     ├─ 기본값: 프로젝트 패널이 오른쪽(사이드바와 동시에 열리도록)
     └─ 우클릭으로 임의 패널을 좌/우 도킹 전환 가능
        │
[5] 멀티 프로젝트 관리
     ├─ 하나의 프로젝트에 폴더 추가(zed 클라이언트 + zed.dev 웹사이트)
     └─ 별도 프로젝트(planets) 열기 → 여러 프로젝트를 오가며 각각에 에이전트 실행
        │
[6] 워크트리 기반 격리 작업
     ├─ "create new worktree based on main" → 무작위 형용사+명사 이름의 새 디렉터리 생성
     │    (예: opal-ravine, ~/code/<repo>/worktrees/ 하위에 생성)
     ├─ 원본 체크아웃과 독립된 완전히 새로운 체크아웃 확보
     └─ 두 프로젝트(zed 클라이언트, zed.dev) 모두에 대해 워크트리 생성 가능
        │
[7] 실제 작업 위임 — "extensions 개념을 전부 plugins로 리네이밍"
     ├─ 풀스크린 해제 후 에이전트의 실시간 편집 과정을 관찰
     ├─ Git 브랜치 diff로 원본 브랜치(main) 대비 변경사항 확인
     └─ 작업 중에도 다른 프로젝트로 전환해 별도 작업 계속 가능
        │
[8] 커밋 및 정리
     ├─ Git 패널에서 변경사항 스테이징
     ├─ 워크트리 생성 시 브랜치가 없었으므로 새 브랜치(plugins) 생성 후 커밋
     ├─ Publish 버튼으로 푸시
     └─ 스레드 보관(Archive Thread)
          ├─ 사이드바에서 스레드 제거 + 미커밋 변경분을 Git 저장소 내 임시 커밋으로 이관
          ├─ 빌드 산출물 등 Git-ignore 대상 파일은 디스크에서 삭제(공간 절약)
          └─ "Show Thread History"로 언제든 복원 가능 — 복원 시 동일한 diff 상태로 정확히 복귀
        │
[9] 마무리 — 사이드바 숨기고 코드에 집중하는 모드로 전환 가능
```

## 상세 내용

영상은 화면 녹화 기반 데모로, 내레이터(제드 팀원으로 추정)가 실제 조작 화면을 보여주며 설명한다. 오프닝에서 "Zed를 오랜만에 열었다면 외부 에이전트로부터 스레드를 가져오라는 메시지를 보게 될 것"이라며, Amp·Claude·Codex·Cursor·Open Code 등 이미 설치된 서드파티 에이전트의 기존 스레드를 한 번에 임포트하는 기능을 먼저 보여준다.

임포트가 끝나면 스레드 히스토리 뷰에서 언제든 접근할 수 있다는 점을 강조한 뒤, 새 프로젝트(Zed 클라이언트 자체 저장소)를 열어 처음부터 시연을 시작한다. 첫 스레드는 화면을 전체화면으로 확장해 에이전트에만 집중하는 모드로 시작하며, "README를 기반으로 이 프로젝트를 설명해달라"는 프롬프트를 입력한다.

이 작업이 진행되는 동안 내레이터는 사이드바에서 실행 중인 스레드를 중단할 수 있다는 점, 그리고 같은 화면에서 곧바로 새 스레드를 추가로 시작할 수 있다는 점을 보여준다. 두 번째 스레드는 에이전트를 클로드로 바꿔 같은 질문을 반복하고, 이어서 세 번째 스레드는 커서 에이전트로 다시 같은 질문을 던진다. 세 스레드가 동시에 실행되다가 순서대로 완료되면 사이드바에 파란 점(안 읽음 표시)이 뜨고, 클릭하면 해당 에이전트의 아이콘으로 바뀐다. 내레이터는 "결과는 에이전트마다 산출 방식이 달라 다를 수 있지만, 핵심은 예전처럼 별도의 Zed 창을 여러 개 열지 않고도 이 에이전트들을 병렬로 돌릴 수 있다는 것"이라고 강조한다.

레이아웃 관련해서는 기본적으로 프로젝트 패널이 화면 오른쪽으로 옮겨졌다는 점을 짚는다. 스레드 사이드바와 동시에 열려 있을 수 있도록 하기 위한 배치 변경이며, 원한다면 우클릭으로 어떤 패널이든 좌/우 도킹 위치를 다시 바꿀 수 있다.

이어서 멀티 프로젝트 시나리오로 넘어간다. 기존 zed 클라이언트 프로젝트에 zed.dev 웹사이트 폴더를 추가해 하나의 프로젝트 안에 두 개의 폴더를 두는 방법과, 완전히 별도의 두 번째 프로젝트(planets 디렉터리)를 여는 방법을 모두 보여준다. planets 프로젝트에서는 새 스레드를 만들면서 "create new worktree based on main" 옵션을 선택하는데, 이때 Zed가 무작위 형용사+명사 조합(예: opal-ravine)으로 워크트리 이름을 자동 생성하고, 홈 디렉터리의 프로젝트 폴더 하위에 worktrees라는 디렉터리를 만들어 그 안에 새 체크아웃을 배치하는 과정을 터미널 화면으로 직접 확인시켜준다.

내레이터는 워크트리의 장점을 "기존 체크아웃(이 경우 origin/main)을 건드리지 않고 Git이 로컬에서 관리할 수 있는 새 폴더에 완전히 새로운 체크아웃을 만드는 방법"이라고 설명한다. 처음에는 이 워크트리에 브랜치가 연결돼 있지 않다는 점도 짚는다. 이 상태에서 새 에이전트를 실행해 "프로젝트에 대해 설명해달라"고 시키고, 작업이 진행되는 동안 다른 프로젝트로 전환해 그쪽에서도 새 워크트리를 만든다. 이번에는 zed 클라이언트 저장소뿐 아니라 zed.dev 웹사이트 저장소에도 워크트리를 만들어, 결과적으로 두 프로젝트 모두 원본을 건드리지 않는 새 체크아웃 상태에서 에이전트가 작업하도록 구성한다.

실제 위임 작업으로는 "extensions라는 개념을 전부 plugins로 바꿔달라"는 대규모 리네이밍 작업을 제시한다. 시간이 걸리는 작업이므로, 전체화면 모드를 해제하고 에이전트가 실시간으로 코드를 수정하는 과정을 지켜볼 수 있다는 점을 보여준다. 동시에 "Git 브랜치 diff" 기능을 사용해 원본 브랜치(main) 대비 현재 변경사항을 나란히 비교하는 화면도 시연하며, "extensions, plugins, extensions, plugins" 식으로 문자열이 바뀌어가는 실제 diff를 보여준다. 이 작업이 백그라운드에서 계속 진행되는 동안에도 언제든 Git diff를 확인할 수 있다는 점이 강조된다.

작업이 충분히 진행됐다고 판단되면 에이전트를 중단하고, Git 패널에서 변경사항을 스테이징한다. 이때 워크트리 생성 시 브랜치를 만들지 않았기 때문에 그대로 커밋하면 어떤 브랜치에도 속하지 않는 상태가 된다는 점을 지적하며, "plugins"라는 새 브랜치를 만들어 그 위에서 커밋("extensions to plugins")하고 Publish 버튼으로 푸시하는 과정을 마무리한다.

마지막으로 다루는 기능은 스레드 보관(Archive Thread)이다. 더 이상 쓰지 않는 스레드를 정리할 때 사용하며, 보관 버튼을 누르면 사이드바에서 스레드가 사라질 뿐 아니라 해당 워크트리 폴더의 내용(커밋되지 않은 변경분 포함)이 Git 저장소 안에 일종의 백그라운드 임시 커밋 형태로 이관된다. 이 과정에서 빌드 디렉터리 등 Git이 무시하는 임시 파일들은 실제로 디스크에서 삭제돼 저장공간을 절약하는 효과가 있다고 설명한다. 다시 필요하면 "Show Thread History"에서 해당 스레드를 찾아 클릭하는 것만으로 모든 파일이 디스크에 복원되고, 보관 전과 동일한 Git diff 상태로 정확히 되돌아온다는 점을 실제로 시연해 보여준다. 완전히 삭제하고 싶다면 "Delete Thread" 버튼을 별도로 제공한다.

영상은 사이드바를 숨기고 코드 자체에 집중하는 모드로 전환할 수 있다는 점을 보여주며 마무리되고, 내레이터는 개인적으로 이 사이드바를 항상 열어두고 여러 프로젝트와 에이전트 작업을 오가는 용도로 쓰고 있다고 소감을 밝힌다.

## 실무 팁 정리

- 스레드 사이드바 단축키는 macOS 기준 option-cmd-j(다른 OS는 ctrl-option-j)로 자막에서 언급되지만, 정확한 표기는 실제 사용 시 재확인이 필요하다.
- 외부 에이전트(Claude Code, Codex 등)에서 이미 진행 중이던 스레드도 임포트 기능으로 그대로 Zed 안으로 가져올 수 있다.
- 워크트리 이름은 자동으로 무작위 생성되며(형용사+명사 조합), 위치는 프로젝트 폴더 하위의 `worktrees/` 디렉터리다.
- 워크트리로 시작한 작업은 기본적으로 브랜치가 없는 상태이므로, 커밋 전 별도로 브랜치를 만들어야 한다.
- 스레드 보관은 디스크 공간 절약과 사이드바 정리를 동시에 해결하며, 복원 시 완전히 동일한 상태로 되돌아오므로 삭제와는 다른 개념이다.
