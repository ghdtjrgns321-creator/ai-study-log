# 오늘의 AI 개념: 소형언어모델과 온디바이스 에이전틱 AI(Small Language Model, SLM)

> 작성일: 2026-07-29 · 분류: ai-concept

## 한 줄 정의

모든 일을 하나의 거대한 범용 AI에게 맡기는 대신, 정해진 업무만 잘하도록 작게 만든 AI 모델을 기기 안에서 직접 돌리는 접근이다.

## 쉬운 설명

거대 병원에 만능 명의 한 명을 두는 대신, 채혈·엑스레이 등 각 업무를 잘하는 전문 인력을 부서마다 배치하는 것과 비슷하다. SLM(Small Language Model)은 파라미터 수가 수십억(B) 단위로, 수백억~수천억 단위인 대형 언어모델(LLM)보다 작다. 온디바이스는 이 작은 모델을 클라우드가 아니라 노트북·스마트폰 같은 기기 자체에서 실행한다는 뜻이다.

흥미로운 점은 이 흐름을 정리한 논문이 다름 아닌 엔비디아에서 나왔다는 것이다. 대형 LLM 구동에 필요한 GPU를 팔아 가장 크게 성장한 회사가, "에이전틱 AI 시대에는 LLM보다 SLM이 낫다"는 논문을 낸 것이다. 근거는 실제 에이전트가 수행하는 하위 작업 대부분이 반복적이고 범위가 좁다는 데 있다 — 좁은 업무에는 좁은 모델이면 충분하다는 논리다.

07-22에 다룬 확산 언어모델(DLM)이 텍스트를 생성하는 방식 자체의 차이였다면, SLM/온디바이스는 모델의 크기와 실행 위치에 관한 차이다. 07-19에 다룬 LLM 라우팅·캐스케이드가 클라우드 안에서 크고 작은 모델을 골라 쓰는 것이었다면, 이번 개념은 클라우드를 아예 거치지 않고 기기 안에서 끝까지 처리하는 경우까지 포함한다.

## 동작 원리

엔비디아 논문은 범용 LLM 에이전트를 특화 SLM 에이전트로 바꾸는 절차를 이렇게 제시한다.

```
① 사용자 데이터 수집   — 입력 프롬프트·출력 응답·툴 호출 로그를 모은다
② 데이터 큐레이션·필터링 — 민감 정보를 제거한다
③ 태스크 클러스터링    — 반복되는 작업 패턴을 그룹으로 묶는다
④ 그룹별 SLM 선정      — 각 패턴에 맞는 작은 특화 모델을 배치한다
```

에이전트 구조는 두 형태로 나뉜다. 큰 언어모델이 인터페이스 역할을 하며 도구를 직접 호출하되 세부 작업은 SLM에 위임하는 방식, 또는 컨트롤러가 언어모델에 요청하고 도구에서 응답을 받는 과정을 반복하는 코드형 구조다. 어느 쪽이든 "필요한 만큼만 큰 모델을 쓴다"는 원칙은 같다.

## 구체 예시·사례

논문이 든 사례는 구체적이다. Microsoft Phi-2는 상식 추론 점수가 300억(30B) 파라미터급 모델과 비슷하면서 속도는 15배 빠르다고 소개된다. 엔비디아 자체 모델 Hymba(20~90억 파라미터, Mamba-Transformer 하이브리드)는 코드 생성에서 30B급과 견줄 만하다. Salesforce의 80억(8B) 파라미터 모델은 툴 호출 성능이 GPT-4·Claude 3.5와 비슷한 수준이라고 소개된다. 다만 이 수치들은 모두 논문·벤더 자체 벤치마크이며 독립 재검증 결과는 확인되지 않는다.

## 비슷한 것과 비교

| 구분 | 범용 LLM(클라우드) | SLM(온디바이스·특화) |
|---|---|---|
| 강점 | 폭넓은 추론·대화 능력 | 낮은 지연·비용, 데이터 반출 없음 |
| 한계 | 인프라·비용 부담이 큼 | 범위 밖 작업에는 취약 |
| 언제 쓰나 | 판단·창의성이 필요한 고난도 업무 | 정형화된 반복 업무, 민감 데이터 처리 |

선택 기준: 업무가 반복적·정형적이고 데이터를 외부로 보내기 어렵다면 SLM, 처음 보는 문제를 유연하게 판단해야 한다면 LLM을 쓰는 하이브리드 조합이 실무의 방향이다.

## 왜 지금 중요한가

엔비디아가 GPU 매출 대부분을 대형 LLM 인프라에서 얻으면서도 SLM의 우위를 주장하는 논문을 낸 점 자체가, 업계가 에이전틱 AI의 무게중심을 "더 큰 모델"에서 "더 적합한 크기의 모델"로 옮기고 있다는 신호로 받아들여진다. 여러 업계 분석은 기업들이 앞으로 범용 모델보다 업무 특화 소형 모델을 점점 더 채택할 것으로 전망하는데, 정확한 배율은 출처마다 달라 방향성으로만 이해하는 편이 안전하다.

## 회계법인 AI 직무 연결 포인트

한국공인회계사회의 감사 데이터 분석 도구 알파라이저(Alphalyzer)는 AI Assistant 기능에서 ChatGPT·Gemini·Claude 같은 클라우드 모델뿐 아니라 로컬 LLM(Gemma)도 지원한다. 고객사의 민감한 재무 데이터를 외부로 보내지 않고 로컬 환경에서 1차 분석을 돌릴 수 있어, 데이터 반출 규정을 지켜야 하는 감사 현장에 유리하다.

전표 분류, 계정과목 매칭처럼 반복적인 업무는 저비용 SLM으로 처리하고, 이상 거래에 대한 최종 판단처럼 맥락 이해가 필요한 업무만 고가의 프론티어 모델로 넘기는 하이브리드 구조는 감사 원가 절감의 실무적 방향이 될 수 있다.

감사 대상 기업 스스로가 SLM 기반 에이전트를 재무 프로세스에 심는 사례도 늘어날 것으로 보이는데, 이 경우 감사인은 "그 소형 모델이 어떤 데이터·규칙을 근거로 분개를 만들었는지"까지 새로운 감사 대상으로 다뤄야 한다.

## 핵심 용어·논쟁

- **SLM** — 파라미터 수가 상대적으로 적은 경량 언어모델.
- **온디바이스 AI** — 클라우드 서버를 거치지 않고 기기 자체에서 AI 모델을 실행하는 방식.
- **툴 콜링(Tool Calling)** — AI 모델이 외부 함수·API를 호출해 작업을 수행하는 능력.

SLM이 실제로 프론티어 모델과 대등한 성능을 내는지에 대한 근거는 대부분 벤더 자체 벤치마크이며, 독립 기관의 재검증 결과는 아직 충분히 축적되지 않았다는 점에 주의가 필요하다.
