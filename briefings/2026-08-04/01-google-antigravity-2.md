# 오늘의 AI 개념: 구글 안티그래비티 2.0(Google Antigravity 2.0)

> 작성일: 2026-08-04 · 분류: agentic-coding

## 한 줄 정의

구글 안티그래비티 2.0은 개발자가 코드 편집기 없이도 여러 AI 에이전트를 동시에 지시·관리할 수 있게 만든 구글의 독립형 에이전트 코딩 플랫폼이다.

## 쉬운 설명

기존 안티그래비티 1.0은 VS Code를 포크해서 만든 편집기 형태였다. 편집기 안에 에이전트가 곁다리로 붙어있는 구조였고, 사람이 여전히 코드 화면을 보면서 작업을 확인해야 했다.

2.0은 접근 자체를 뒤집었다. 편집기가 중심이 아니라 "에이전트 관리 화면"이 중심이다. 사람은 프로젝트 폴더를 지정하고 목표를 지시한 뒤, 여러 에이전트가 병렬로 작업하는 것을 대시보드에서 지켜보다가 승인이 필요한 순간에만 개입한다.

비유하자면 1.0은 조수 한 명을 옆에 앉혀놓고 코드를 같이 치는 방식이었고, 2.0은 여러 팀원에게 업무를 나눠준 뒤 진행 상황판을 보며 관리하는 팀장의 자리로 옮겨간 것이다. 실제로 2.0은 메인 에이전트가 필요에 따라 하위 작업용 서브에이전트를 스스로 만들어내는 구조를 갖췄다.

비슷한 도구인 Cursor Composer나 OpenAI Codex와 비교하면, 안티그래비티 2.0은 데스크톱 앱·CLI·SDK·클라우드 매니지드 에이전트까지 네 가지 형태를 한 번에 제공한다는 점에서 범위가 더 넓다. 다만 그만큼 기존 VS Code 확장 생태계(한국어 언어팩 등)와의 호환성은 포기했다.

## 동작 원리

1. 사용자가 데스크톱 앱, CLI(`ag`), SDK 중 하나로 진입해 작업 폴더를 프로젝트로 지정한다.
2. 목표를 자연어로 지시하면 메인 에이전트(오케스트레이터)가 먼저 계획을 세워 사람에게 제출(submit)한다.
3. 계획이 승인되면 오케스트레이터가 UI/UX 담당, 로직 담당처럼 역할이 다른 서브에이전트를 동적으로 생성해 병렬로 실행시킨다.
4. 각 서브에이전트의 진행 상황은 대시보드에서 실시간으로 확인할 수 있고, 필요하면 개별 서브에이전트 화면에 들어가 세부 작업을 살펴볼 수 있다.
5. 브라우저 사용 권한을 켜면 에이전트가 직접 웹 화면을 띄워 만든 결과물을 실행·검증한다.
6. 데스크톱 앱과 CLI는 같은 프로젝트 폴더를 공유하므로, 한쪽에서 지시한 수정 사항이 다른 쪽 화면에도 실시간으로 반영된다.

## 구체 예시·사례

구글 공식 발표에 따르면 안티그래비티 2.0은 2026년 5월 19일 구글 I/O에서 공개됐고, 기본 모델로 제미나이 3.5 플래시(Gemini 3.5 Flash)를 탑재했다. 구글은 이 조합이 코딩·에이전틱 벤치마크에서 경쟁 프론티어 모델보다 4배 빠르게 동작한다고 밝혔으며, API 키를 등록하면 클로드 소네 4.6·오퍼스 4.6 등 다른 벤더 모델로 바꿔 쓸 수도 있다.

실사용 후기(유튜브 자막 확인)에서는 "약 복용 알림 서비스를 오케스트레이터·서브에이전트 구조로 만들어달라"고 지시하자, 에이전트가 먼저 계획을 세우고 UI/UX 서브에이전트와 로직 서브에이전트 두 개를 동시에 실행해 화면 설계와 데이터 처리를 병렬로 완성한 사례가 확인된다. 완성 후에는 에이전트가 직접 브라우저를 띄워 복약 등록·상담 기능이 정상 동작하는지까지 검증했다.

## 비슷한 것과 비교

| 항목 | 안티그래비티 1.0 | 안티그래비티 2.0 | Cursor Composer / OpenAI Codex |
| --- | --- | --- | --- |
| 형태 | VS Code 포크 편집기 | 독립형 데스크톱 앱 + CLI + SDK + 매니지드 에이전트 | IDE 내장형(Cursor) / CLI·클라우드형(Codex) |
| 중심 UI | 코드 에디터 | 에이전트 매니저(프로젝트 대시보드) | 채팅·인라인 편집(Cursor), 태스크 목록(Codex) |
| 서브에이전트 | 제한적 병렬 실행만 지원 | 오케스트레이터가 서브에이전트를 동적 생성 | Codex는 클라우드 태스크 병렬 실행 지원 |
| 기본 모델 | 제미나이 3.1 프로 | 제미나이 3.5 플래시(멀티 벤더 전환 가능) | 벤더별 자체 모델 |

선택 기준: 여러 에이전트를 팀처럼 굴리며 진행 상황을 한눈에 관리하고 싶다면 안티그래비티 2.0이 적합하고, 에디터 화면에서 직접 코드를 다듬는 밀착형 페어 프로그래밍이 목적이라면 Cursor 같은 IDE 내장형이 더 맞다.

## 왜 지금 중요한가

구글은 2026년 5월 19일 I/O 2026에서 안티그래비티 2.0을 정식 공개했다. 이전까지 단일 VS Code 포크였던 도구를 데스크톱 앱·Go 기반 CLI·SDK·Gemini Enterprise Agent Platform을 통한 매니지드 에이전트 서비스까지 네 가지 형태로 동시에 출시한 것으로, 기존 제미나이 CLI를 흡수·대체했다.

실사용 유튜브 리뷰(2026년 5월 21일 게시)에서는 출시 초기 오류가 잦다는 불만이 많았지만, 이후 안정화되며 서브에이전트·스킬·스케줄 기능이 추가돼 Claude Code나 Codex와 견줄 만한 완성도를 보인다는 평가가 나온다.

## 회계법인 AI 직무 연결 포인트

감사·재무 데이터 분석에서 화면(대시보드) 개발, 데이터 파이프라인 스크립트, 내부 자동화 도구를 동시에 여러 갈래로 만들어야 할 때, 오케스트레이터가 서브에이전트를 나눠 병렬로 처리하는 구조는 개발 인력이 적은 회계법인 IT·데이터 조직에 실질적인 생산성 이득을 준다.

또한 브라우저 자동 실행·검증 기능은 자체 개발한 내부 감사 도구나 대시보드가 실제로 의도대로 동작하는지 사람이 일일이 클릭해보지 않아도 에이전트가 대신 확인해준다는 점에서, 통제 테스트 자동화 도구 개발 시 QA 공수를 줄이는 데 활용할 수 있다.

다만 벤더를 자유롭게 바꿀 수 있는 구조인 만큼, 어떤 모델·벤더에 회계 데이터가 실제로 전달되는지 계약·보안 검토 없이 무분별하게 API 키를 연결하는 것은 데이터 거버넌스 관점에서 별도 통제가 필요하다.

## 핵심 용어·논쟁

- **오케스트레이터(Orchestrator)** — 전체 목표를 받아 계획을 세우고 서브에이전트를 동적으로 만들어 작업을 분배하는 메인 에이전트.
- **에이전트 매니저(Agent Manager)** — 여러 에이전트의 작업 상태를 한 화면에서 확인·승인하는 대시보드 UI.
- **매니지드 에이전트(Managed Agent)** — 로컬이 아니라 구글 클라우드(Gemini Enterprise Agent Platform)에서 실행·관리되는 에이전트 형태.
- **워크스페이스→프로젝트(Workspace to Project)** — 1.0에서 "워크스페이스"로 부르던 작업 단위가 2.0에서 "프로젝트"로 개편된 것.
- 진행 중인 논쟁: 출시 직후에는 "OpenAI Codex의 UI를 따라 했다"는 비판과 함께, 기존 워크플로우·룰 설정이 강제 업그레이드로 인해 사라졌다는 불만이 커뮤니티에서 제기됐다. 이후 안정화 평가가 늘고 있지만, 무료 사용량 정책이 짧은 주기로 계속 바뀌는 점은 여전히 불확실성으로 남아 있다.

## 자가 점검 질문

1. 안티그래비티 2.0의 "오케스트레이터-서브에이전트" 구조가 1.0의 병렬 실행 방식과 근본적으로 무엇이 다른가.
2. 회계법인 내부 도구 개발에 이런 멀티 에이전트 병렬 구조를 도입한다면, 어떤 업무에 가장 먼저 적용해볼 수 있을까.
3. 벤더를 자유롭게 전환할 수 있는 플랫폼에서 회계 데이터를 다루려 할 때, 어떤 보안·거버넌스 검토가 선행되어야 하는가.
