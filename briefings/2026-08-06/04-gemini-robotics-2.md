# 오늘의 AI 개념: 제미나이 로보틱스 2(Gemini Robotics 2)

> 작성일: 2026-08-06 · 분류: trend

## 한 줄 정의

제미나이 로보틱스 2는 구글 딥마인드가 2026년 7월 30일 공개한 로봇용 AI 모델 스위트로, 휴머노이드 로봇의 발끝부터 손끝까지 전신을 실시간으로 제어하고 여러 로봇이 하나의 작업을 나눠 수행하도록 만드는 것을 목표로 한다.

## 쉬운 설명

지금까지 로봇에게 "카메라로 보고, 언어로 이해하고, 실제로 움직인다"는 3단계를 모두 자연스럽게 잇는 일은 매우 어려웠다. 사람은 물뿌리개를 보면 그것이 무엇인지 알고, "선반 밑칸 초록 통에 넣어줘"라는 말을 이해하고, 걸어가서 정확히 집어 옮기는 일을 별생각 없이 해낸다. 제미나이 로보틱스 2는 이 세 단계를 하나의 모델 계열로 묶어, 로봇이 걷고 웅크리고 몸을 굽히는 전신 동작과 물체를 손끝으로 정밀하게 다루는 동작을 동시에, 복합적인 작업 추론과 함께 수행하도록 만든 것이다.

비유하자면 기존 산업용 로봇팔이 "정해진 좌표로만 움직이는 자동문"이었다면, 이번 모델은 "지시를 듣고 스스로 동선과 손동작을 계획하는 집사"에 가깝다. 작년에 나온 1세대 제미나이 로보틱스가 주로 탁상 위 상체 조작에 머물렀다면, 이번 버전은 하체 이동·장애물 회피까지 포함한 전신 제어로 범위를 넓혔다는 점이 핵심 차이다.

구성은 세 가지 모델로 나뉜다. 시각·언어 입력을 실제 모터 동작으로 바꾸는 표준형 VLA(Vision-Language-Action) 모델 "제미나이 로보틱스 2", 사람과 소통하고 여러 단계 작업을 계획하며 여러 로봇을 조율하는 임베디드 추론 모델 "제미나이 로보틱스 ER 2", 그리고 로봇 기기 안에서 직접 실행되는 경량 모델 "제미나이 로보틱스 온디바이스 2"다. 이 세 모델은 각자 따로 쓰이기도 하고 함께 결합해 쓰이기도 한다.

## 동작 원리

세 모델은 역할을 분담해 하나의 파이프라인처럼 작동한다.

```
[사람의 지시]                "물뿌리개를 맨 아래 선반 초록 통에 넣어줘"
      │
      ▼
[제미나이 로보틱스 ER 2]     장면을 이해하고 다단계 계획 수립
(체화 추론 / 작업반장)       → "탁자로 이동 → 집기 → 선반으로 이동 → 배치"
      │                       여러 로봇이 있으면 역할 분담까지 조율
      ▼
[제미나이 로보틱스 2 (VLA)]  시각+언어 입력을 관절·모터 명령으로 직접 변환
(전신·손끝 동작 실행)        → 걷기·굽히기·손끝 20여 개 관절 제어를
                               동일한 학습 방식으로 함께 훈련
      │
      ▼
[제미나이 로보틱스 온디바이스 2]  클라우드 연결 없이 로봇 내부에서 저지연 실행
                                    새 로봇 형태에도 소량 데이터로 빠르게 적응
```

VLA 모델은 몸통 제어와 손끝 제어를 별도로 다루지 않고 같은 학습 방식으로 함께 훈련했다는 점이 특징이다. 상위의 ER 2가 "무엇을, 어떤 순서로 할지"를 판단하면, VLA가 그 계획을 실제 관절 동작으로 옮기고, 온디바이스 모델은 통신 지연이 문제가 되는 산업 현장 등에서 로봇 내부에서 직접 동작한다.

## 구체 예시·사례

파트너사 Apptronik의 휴머노이드 로봇 "아폴로 2(Apollo 2)"로 진행된 시연이 대표적이다. "물뿌리개를 맨 아래 선반의 초록색 통에 넣어줘"라는 지시를 받으면, 로봇은 탁자로 걸어가 물뿌리개를 집고, 몇 걸음 이동해 선반 앞에서 정확한 위치에 내려놓는다. 이 과정에서 걷기·장애물 회피·물체 인식·손끝 배치가 하나로 이어진다. 손끝 조작 시연에서는 다섯 손가락 손을 장착한 아폴로 2가 포도를 지퍼백에 넣고 봉투를 닫거나, 구형 전구를 손끝으로 정밀하게 잡아 풀어내거나, 쓰레기봉투를 매듭으로 묶는 등 다지형(multi-fingered) 손이 필요한 정교한 작업을 수행한다. 이런 협응 동작은 산업 로봇의 단순 반복 동작과 달리 매번 물체의 위치·형태가 조금씩 달라도 대응해야 한다는 점에서 난이도가 높다.

## 비슷한 것과 비교

| 구분 | 규칙 기반 산업용 로봇팔 | 제미나이 로보틱스(1세대, 2025) | 제미나이 로보틱스 2(2026) |
| --- | --- | --- | --- |
| 동작 결정 방식 | 사전 프로그래밍된 좌표·경로 | VLA로 언어·시각 입력을 동작으로 변환 | VLA + ER(계획) + 온디바이스로 역할 분담 |
| 제어 범위 | 정해진 팔 동작만 | 주로 상체·탁상 위 조작 | 하체 이동 포함 전신 제어 |
| 환경 변화 대응 | 취약함(환경이 조금만 바뀌어도 오작동) | 어느 정도 일반화 | 장애물 회피 등 동적 대응 강화 |
| 다중 로봇 협업 | 없음 | 제한적 | ER 2가 여러 로봇의 역할 분담을 조율 |

선택 기준을 단순화하면, 정해진 환경에서 반복 작업만 하면 되는 경우는 여전히 규칙 기반 산업용 로봇이 경제적이고, 예측 불가능한 환경에서 언어 지시로 다양한 작업을 시켜야 한다면 VLA 계열 모델이 필요하다.

## 회계법인 AI 직무 연결 포인트

로보틱스는 언뜻 회계·감사와 거리가 멀어 보이지만, 이 모델의 핵심 구조인 "본다(Vision) → 이해한다(Language) → 행동한다(Action)"는 패턴 자체는 회계법인이 개발 중인 문서 처리 에이전트와 계열이 같다. 청구서·계약서 이미지를 보고, 그 내용을 언어로 이해해 승인·반려·플래그 같은 행동으로 옮기는 감사 자동화 에이전트도 구조적으로는 VLA와 동일한 흐름을 따른다. 즉 로봇 제어에 쓰이는 "인지-판단-행동" 파이프라인 설계 원리는 물리적 로봇이 아니어도 그대로 참고할 수 있는 아키텍처 패턴이다.

더 직접적인 접점은 실물자산 검증이다. 감사 절차 중 재고자산 실사는 전통적으로 사람이 창고를 돌며 눈으로 세고 확인하는 노동집약적 절차인데, 전신 제어와 손끝 조작 능력을 갖춘 로봇이 카메라·센서로 재고를 스캔하고 필요하면 직접 물건을 옮기거나 재배치하며 실사를 보조하는 미래 시나리오가 업계에서 논의되고 있다. 다만 이는 아직 상용화된 감사 절차가 아니라 기술적 가능성 수준이며, 손끝 조작이 여전히 로보틱스의 미해결 난제로 남아 있는 만큼 시기를 특정하기는 이르다.

더 넓게 보면 물리 세계로 AI가 확장되는 흐름(Physical AI)은 회계법인 입장에서 실물자산·재고·고정자산의 존재성(existence)과 완전성(completeness)을 검증하는 감사 목표 자체를 기술이 어떻게 재정의할지를 예고하는 사례로 볼 수 있다. 당장의 실무 변화보다는, 감사 증거 수집 방식이 "사람의 육안 확인"에서 "AI-로봇 협업 확인"으로 옮겨갈 가능성을 미리 이해해 두는 관점에서 의미가 있다.

## 핵심 용어·논쟁

- **VLA(Vision-Language-Action) 모델** — 시각·언어 입력을 직접 로봇의 모터 동작으로 변환하는 파운데이션 모델 유형.
- **전신 제어(Whole-body control)** — 로봇의 하체 이동부터 손끝까지 모든 부위를 하나의 모델이 통합적으로 제어하는 방식.
- **체화 추론(Embodied Reasoning)** — 로봇이 물리 환경을 이해하고 다단계 작업을 계획하는 상위 판단 능력. ER 2가 이 역할을 맡는다.
- **손끝 조작(Dexterity)** — 물체를 정밀하게 쥐고 다루는 능력. 로코모션(이동)에 비해 여전히 미해결 난제로 꼽힌다.
- **다중 로봇 협업(Multi-robot collaboration)** — 서로 다른 형태의 로봇들이 소통하며 하나의 작업을 분담·조율하는 능력.

현재 논쟁거리는 로봇 학습용 물리 상호작용 데이터의 부족이다. 딥마인드 연구진은 인터넷에 "물리적 상호작용의 인터넷"이 존재하지 않는다는 점을 데이터 병목으로 지목하며, 원격조작 데이터(품질은 높지만 비용이 커 확장성이 낮음)와 사람의 1인칭 영상 데이터(양은 많지만 힘·구동 라벨이 없어 활용이 어려움) 사이에서 어떤 방식으로 확장 가능한 데이터를 모을지가 미해결 과제로 남아 있다.

2. 이 모델의 "인지-판단-행동" 파이프라인 구조를 회계 감사용 문서 처리 에이전트에 적용한다면 어떤 입력·출력으로 바꿔 설계할 수 있는가?
3. 온디바이스 모델의 빠른 적응 속도는 벤더 자체 발표 수치라는 점에서, 이를 실무 판단 근거로 쓰기 전에 어떤 추가 검증이 필요한가?
